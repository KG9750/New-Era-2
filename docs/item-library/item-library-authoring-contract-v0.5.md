## 2. 边界

C5 只冻结候选物品、代表工艺、储存与污染职责、静态耐久职责和跨批接口，不冻结：

- 食物营养值、饱腹值、口味、精确保质期或自动配餐；
- 药物剂量、治疗概率、生命值、疾病模型或自动诊疗；
- 工具效率百分比、电子设备精度、通信距离、灯具亮度或终端容量；
- 电网、联网服务、远程控制、自动库存管理或自动补货；
- 正式货币、品质概率、技能经验曲线或运行时数值；
- 运行时导入器、UI、存档或 Gate 范围。

食品入库不等于人物已经进食；医疗用品入库不等于伤病已经治疗；工具与电子设备入库不等于相关工艺、通信、照明或管理能力自动生效。

## 4. C5 物品合同

所有 C5 物品继续遵守 V0.1 的库存字段合同。

### 4.1 批量零部件、食品和医疗用品

22 个 `bulk_material` 必须：

- 可堆叠；
- 以批次、污染、新鲜度、浓度、合法性或归属阻止错误合并；
- 有至少一个获得路径和一个消耗或流失路径；
- 不伪造独立实例耐久；
- 食品使用食品安全、干燥、阴凉、冷藏或防污染规则中的适当组合；
- 医疗用品必须明确无菌、包装、污染、剂量责任或专业使用边界；
- 药物名称只表示候选用途族，不冻结治疗效果或适应症全集。

### 4.2 独立工具和电子设备

4 个工具与 4 个电子设备是 `independent_item`，继续使用 V0.2 的 `durability_profile`：

- `tracked: true`；
- C5 不新增维修或拆解工艺时只能使用 `maintain_only` 与 `restricted`；
- 必须声明磨损来源和可见失效后果；
- 电子设备必须声明本地、离线、物理隔离或有线职责；
- 不冻结工具效率、设备精度、通信距离、照明强度或数据容量。

### 4.3 食品边界

- `base_value` 不是营养值或固定售价；
- `freshness` 只负责批次分离，不冻结精确腐坏计时；
- 保存食品仍可能因包装、潮湿或污染失效；
- 食品工艺必须消耗真实原料、燃料、容器或人物有效时间；
- 食物不得仅因存放在仓库中产生人物或聚落增益。

### 4.4 医疗边界

- 每项医疗物品必须说明用途情境与专业使用条件；
- 抗生素、止痛药、止血敷料等不声明即时恢复值或统一治疗效果；
- 医疗效果仍取决于伤病类型、使用时机、人物资格、卫生、工具和后续休养；
- 战备预留必须从普通医疗库存中扣除，不能重复承诺；
- 受控药物必须有可追踪批次、上锁储存和污染或失效路径。

## 5. C5 工艺合同

15 个工艺分布：

| 内容链 | 工艺数 |
|---|---:|
| 电气与机械组件 | 5 |
| 工具装配 | 1 |
| 电子设备装配 | 2 |
| 食品加工 | 5 |
| 医疗加工 | 2 |
| **合计** | **15** |

约束：

- 所有工艺必须有非空输入和主产出；
- 副产物必须引用库存物品或受控负担，也允许诚实的空数组；
- 食品加工必须明确食品安全、污染、燃料和储存窗口；
- 医疗加工必须明确清洁工作区、专业资格、污染风险和用途边界；
- 电子装配只生产设备，不自动部署、供电、联网或产生预警；
- 工具装配只生产可分配工具，不自动缩短任何运行时任务；
- 工艺继续连接设施、工具、资格、人物有效时间和物流。

## 6. 接口覆盖层

`items.c5.yaml.interface_extensions` 可以向 C1–C4 的既有库存物品追加 C5 工艺引用。它：

- 只能引用 C5 工艺；
- 只能追加 `produced_by`、`used_by`、`repair_recipes` 或 `dismantle_recipes`；
- 不得覆盖、删除或重复前批接口；
- 不得向非库存定义追加制造接口；
- 合并后必须与工艺输入、产出和副产物精确双向一致。

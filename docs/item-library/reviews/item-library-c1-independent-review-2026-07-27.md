## 2. 第一轮独立审查

第一轮结果：

|---|---:|---|

| P1 | 2 | 需要修正 |

第一轮门禁为 `REVIEW_FAIL`。

### 2.1 P1-1：`salvage_only` 与贸易获得路径冲突

**证据：** 混杂废钢和回收铜线带有“仅回收”标签，同时声明可以通过 `trade` 获得。

**影响：** 标签过滤与获得路径会给出相反结论。

**修正：**

- 保留 `reclaimed` 表达回收来源；
- 从允许贸易的两个物品删除 `salvage_only`；
- 在合同中定义：只有全部获得路径均为 `salvage` 才能使用 `salvage_only`；
- 在校验器中增加该跨字段约束。

**状态：** 已修正并复审通过。

### 2.2 P1-2：`salvage_only` 在同类物品间语义不一致

**证据：** 第一轮审查把“没有本轮制造配方”与“只能回收获得”混为一谈，并指出多个回收件未使用该标签。

**裁定：** 接受“必须明确标签语义”的核心问题，但不接受“无制造配方就必须带 `salvage_only`”这一推导。机械备件、回收电子组件和标记线束都允许贸易获得，因此不属于“仅回收”。

**修正：** 合同和校验器统一把 `salvage_only` 定义为获得路径排他约束，而不是“本轮没有制造配方”。

**状态：** 已修正并复审通过。

### 2.3 P2-1：冻结设计头部 SHA 与当前文件 SHA 不同

**证据：** 冻结设计第 11 行记录的“受审内容 SHA-256”与当前文件实际 SHA 不同。

**裁定：** 驳回，不修改 R1。

理由：

1. 字段名称是“受审内容”，不是“当前文件自哈希”；
2. 把包含哈希文本的文件要求为自身最终 SHA 会产生自指，不能作为可复算合同；
3. C1 各资产使用当前外部核验 SHA `24f0d4f...`，校验器强制它们一致；
4. 本支干明确要求 R1 只引用、不修改。

第二轮独立复审确认没有反证，并接受该驳回。

### 2.4 P2-2：结构化暴露字段与风险标签未同步

**证据：**

- `regulated_batch` 物品未带 `traceable`；
- `wealth_signal: high` 物品未带 `high_wealth_exposure`。

**影响：** 结构化暴露查询与标签筛选会返回不一致结果。

**修正：**

- 为四项 `regulated_batch` 物品补充 `traceable`；
- 为有线预警单元补充 `high_wealth_exposure`；
- 合同声明结构化字段是权威值，标签是受校验的查询索引。

**状态：** 已修正并复审通过。

### 2.5 P2-3：校验器缺少跨字段语义门禁

**证据：** 第一版校验器可以让上述标签矛盾静默通过。

**修正：** 增加三项门禁：

- `salvage_only` 只允许全 `salvage` 获得路径；
- `traceable` 与 `regulated_batch` / `networked` 双向一致；
- `high_wealth_exposure` 与 `wealth_signal: high` 双向一致。

**状态：** 已修正并复审通过。

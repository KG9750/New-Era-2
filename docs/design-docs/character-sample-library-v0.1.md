## 1. 目的与边界

本样板库不是把 50 人候选库缩小成一个可发布名单，而是为阶段 A1 准备六组
可直接测试的“同 MBTI、不同人生路径”对照。

当前完成的是：

- 从已通过机器合同的 50 人候选库中绑定 12 个唯一来源人物；
- 重写每人的履历、第一印象、日常与压力行为、语音和决策场景；
- 为每人写出“去掉 MBTI 后仍成立”的身份说明；
- 设计接受与拒绝都产生代价的玩家选择；
- 固定玩家卡默认隐藏 MBTI 四字母代码；
- 建立八项机器结构校验。

当前未完成的是：

- Gate 1H 的真人“人物可记忆性”证据；
- 根据 Gate 1H 结果回审字段、属性、技能和人格粒度；
- 文化命名包冻结与 E01；
- E02–E06 人工内容审核；
- MBTI 玩家验证；
- 阶段 A1 独立审查与冻结。

因此本包只能作为 A1 输入，不得标记为正式 12 人样板、阶段 A1 通过或阶段 B
人物库。

这 12 人不是职业模板。表中技能只说明候选人物当前较强的宽能力；人物身份仍由
履历、价值观、红线、关系、请求和决策代价共同构成。

## 3. 单个样板的最低内容

每个样板必须包含：

1. 绑定 50 人候选库的来源 ID 与区分度指纹；
2. 正式姓名与聚落关系型称呼，不使用外号、旧代号或 callsign；
3. 重写履历，而非只复制生成器摘要；
4. 第一印象、日常行为、压力行为和一句自然表达；
5. 两项核心价值、预先披露的红线和当前动机；
6. 一个会占用资源或改变关系的可见请求；
7. 一个“接受”和“拒绝”都有明确后果的决策场景；
8. 一段不依赖 MBTI 的身份说明；
9. 一段与同类型人物的实质差异说明；
10. 三个待玩家或审核者回答的验证问题。

## 4. 玩家卡与 MBTI 显示

当前固定：

- JSON 保存 `internal_mbti_type`，只用于内部配对和验证；
- 玩家卡使用 `HIDDEN_IN_PLAYER_CARD_UNTIL_VALIDATED`；
- 人物表达依赖具体行为句，不依赖“某类型通常如何”的说明；
- 不显示代码时，玩家仍应能从履历、请求、价值观和场景判断人物；
- 若未来测试四字母代码的影响，代码可在完成第一轮选择后单独揭示，不得在初次
  阅读时替代人物内容。

未经 MBTI 玩家验证，不得把四字母代码接入正式 UI。

## 6. 人工审核顺序

正式 A1 启动后按以下顺序执行，不允许由机器结果代替：

1. 用 Gate 1H 人物感结果回审当前人物字段；
2. 冻结或修订文化命名包，执行 E01；
3. 逐人执行 E02：能力、属性和资格是否有足够履历依据；
4. 逐人执行 E03：特质、价值观、红线和转折是否形成因果链；
5. 以完整 12 人批次执行 E04：是否把文化、性别、年龄或 MBTI 映射为能力和
   道德；
6. 逐人执行 E05：人物是否真正改变选择、关系或风险；
7. 按六个同类型对照组执行 E06：两人的转折、动机和行为是否仍可区分；
8. 修订失败样板后重新运行机器校验；
9. 执行 MBTI 玩家验证；
10. 由全新上下文 Codex agent 独立审查，要求 P0=0、P1=0。

人工审核结果必须逐人记录证据。当前所有结果均为 `NOT_RUN`。

## 7. MBTI 玩家验证草案

本节只冻结测试问题，不宣称测试已执行。

### 7.1 第一轮：隐藏代码

- 向未参与人物制作的测试者展示人物卡和决策场景；
- 不显示 MBTI 四字母代码；
- 要求测试者复述姓名、经历或红线，以及一次决策影响；
- 将六组同类型人物并排，要求指出至少一项非职业标签的差异；
- 记录测试者是否只用“医疗最高”“工程最高”等数值称呼人物。

### 7.2 第二轮：揭示代码

- 在第一轮回答完成后揭示内部类型；
- 询问测试者是否因此推断职业、善恶、忠诚或能力；
- 询问代码是否比自然语言行为说明更有帮助；
- 记录同类型人物是否被认为可以互换。

### 7.3 删除测试

另存一份删除 MBTI 的人物卡。若删除代码和类型说明后，人物的履历、请求、
关系和决策场景仍然成立，才满足“MBTI 是偏好层而不是人物骨架”的最低要求。

若多数测试者把类型当作职业或道德捷径，应隐藏代码、降低运行时权重或删除
MBTI；不得为了保留既有规格而修改通过标准。

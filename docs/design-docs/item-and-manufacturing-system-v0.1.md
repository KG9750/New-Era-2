## 0. 文档目的与决策状态

本文定义《新纪元 2》的物品、库存、制造、维修、装备、植物与伙伴动物的统一设计框架。它用于指导后续内容库、数据定义、制造界面、战前装备和战利品系统，不是当前运行时实现规格，也不是完整物品清单。

本文需要解决五个问题：

1. 不同类别的物品如何使用同一套基础规则；
2. 物品如何进入周计划、供需推演、地图物流和人物故事；
3. 制造、维修、拆解与装备如何共享材料、设施和人物时间；
4. 非战斗物品如何保持长期价值；
5. 如何建立大型候选物品库，而不提前扩大原型范围。

本文使用三种决策状态：

- **继承基线：** 直接来自概念设计 V0.4，本文不得改变；
- **R1 冻结基线：** 已通过独立复审并由用户冻结；修改时必须说明证据、影响范围和版本变化；
- **待验证：** 只有交互原型、批量模拟或玩家测试能够决定。

### 0.1 继承的设计基线

以下规则已经由 V0.4 确立：

- 日常经营采用连续时间、暂停、多档倍速与人物自主执行；
- 玩家通过生产队列决定设施生产什么，通过周计划决定投入多少人物时间；
- 实际产出同时受到人物、设施、工具、原料、环境和地图物流影响；
- 生存、工业、安全和政治四条资源主链必须共享瓶颈；
- 月度主题不能直接以武器、护甲、弹药或战斗力结算；
- 战前需要锁定人员、武器、弹药、药品、工具和防守预案；
- 战利品受到携带能力、撤离时间、伤员和财富暴露限制；
- P0 的资源、建筑、主题和地图数量必须严格受限。

### 0.2 当前范围边界

当前 Gate 1 仍然只验证两周纯经营切片。本文不会授权以下工作：

- 实现完整库存或制造系统；
- 增加武器、护甲、弹药和战斗；
- 制作完整科技树；
- 把候选物品库全部导入运行时；
- 增加当前切片之外的资源和设施；
- 把本设计提案标记为已经通过玩家验证。

Gate 1 中唯一需要验证的物品样本仍是 **一次完整使用机会的化肥**。它用于验证物品如何影响库存、计划条件、产量区间和偏差解释，不用于证明完整物品系统成立。

## 1. 系统定位

物品系统不是独立的收藏菜单，而是聚落承诺的物质层。

每件进入正式内容的物品，至少应当连接以下一项：

- 生存与日常消耗；
- 生产、维修或空间物流；
- 人物能力、请求、关系或记忆；
- 主题竞争、贸易、礼物或合规风险；
- 战前准备、战术执行或战后恢复。

理想情况下，一件关键物品会同时连接两个以上层面。例如：

> 金属板既可以维修水泵，也可以制成护甲插板或加固路障。  
> 把它用于安全链，就意味着放弃一部分生存或工业稳定。

物品系统的核心体验不是“收齐更多图标”，而是：

> 知道有限材料正在被谁、在何处、为了什么承诺而消耗，  
> 并接受其他用途因此被推迟。

## 2. 设计目标

### 2.1 目标

1. **让物品进入现有因果链。**  
   物品必须能影响周计划、供需预测、地图兑现、人物状态或月末风险。

2. **让民生与军备争夺同一基础。**  
   农具、医疗、住房、主题交付和装备制造不能长期使用彼此隔离的资源池。

3. **让结果可解释。**  
   玩家应能追溯一件成品来自哪些原料、人物、设施、工具和已知风险。

4. **让非战斗物品具有真实用途。**  
   书籍、服饰、家具、装饰、珠宝和日用品不能只是低价值杂物。

5. **控制微操。**  
   高频资源按批次管理，生产由队列和库存目标驱动，玩家不逐颗管理谷粒、钉子和弹头。

6. **支持人物故事。**  
   部分物品可以拥有来源、前任持有者、赠送记录、战斗经历和纪念意义。

7. **允许逐步扩展。**  
   新增内容应优先复用既有属性、标签、工艺和效果通道，而不是为每件物品写专属系统。

### 2.2 非目标

- 不做随机词条驱动的刷装游戏；
- 不做以颜色区分强度的线性稀有度阶梯；
- 不做数百种只改变少量数值的同质武器；
- 不让图纸在获得瞬间替代人物学习和岗位资格；
- 不让仓库里的装饰品自动提供无条件全局增益；
- 不让高级联网设备成为没有风险的必选升级；
- 不要求玩家持续手动给每个人补充每一件低价值消耗品；
- 不在系统尚未验证前制作大量正式内容。

## 3. 三轴分类方法

每个物品同时具有 **内容分类、存在形态和用途标签**。三者承担不同职责，不能互相替代。

### 3.1 内容分类

内容分类用于图鉴、筛选、仓储策略和内容规划。V0.1 使用以下一级分类：

| 一级分类 | 主要内容 |
|---|---|
| 材料 | 金属、木材、石材、织物、玻璃、聚合物、化学原料 |
| 零部件 | 机械件、电气件、滤芯、紧固件、离线控制组件 |
| 工具 | 农具、维修工具、医疗工具、测量工具、制造夹具 |
| 电子用具 | 有线通信、本地终端、传感器、照明、诊断设备 |
| 食品与饮料 | 原粮、鲜食、保存食品、饮料、调味与特殊餐食 |
| 药品与医疗用品 | 绷带、消毒剂、药物、止血用品、夹板、手术耗材 |
| 武器与弹药 | 近战、远程、投掷、弹药、维护耗材 |
| 防具与服饰 | 基础衣物、环境服、防护服、护甲、头部与足部装备 |
| 书籍与数据载体 | 教材、手册、图纸、档案、禁书、只读存储 |
| 家具 | 睡眠、储藏、用餐、卫生、照明、社交与工作家具 |
| 日常用品 | 餐具、容器、清洁、卫生、文具、缝补与个人用品 |
| 装饰与乐器 | 照片、旗帜、手工作品、玩具、纪念物、乐器 |
| 珠宝与贵重品 | 戒指、吊坠、机械表、纪念章和小型价值载体 |
| 植物与种源 | 种子、幼苗、插条、菌种及其采收物 |
| 伙伴与役用动物 | 陪伴、预警、捕鼠、通讯、运输或产出的动物 |
| 文件与凭证 | 身份、配额、审计、所有权、通行、合同和账册 |
| 稀有与特殊物品 | 原型机、工艺样本、旧世界遗物、任务证据 |
| 副产物与废弃物 | 废油、污水、弹壳、破布、碎玻璃、电子废料 |

一级分类只描述玩家如何理解物品，不决定程序形态。例如旧世界军用无线电属于“电子用具”，同时可以带有“稀有”“违禁”“战术通信”和“可追踪”标签。

### 3.2 存在形态

| 形态 | 规则 |
|---|---|
| **批量物资** | 以标准批次或容器管理，可堆叠；适合粮食、材料、药品和弹药 |
| **独立物品** | 单件拥有品质、耐久、来源和分配状态；适合武器、护甲、工具和贵重品 |
| **放置实体** | 从库存部署到地图后，成为可交互设施或家具 |
| **生长实体** | 种子、幼苗或插条种下后，成为拥有生长状态的植物实体 |
| **角色实体** | 伙伴动物拥有需求、关系、伤势和行为，不作为普通库存堆叠 |
| **权利记录** | 证件、资格和部分合同可以表现为文件，也可以转化为聚落或人物记录 |

形态转换必须明确：

```text
种子物品 → 播种任务 → 植物实体 → 收获物品

家具物品 → 搬运与安装 → 放置实体 → 拆卸后返回物品或材料

运输笼中的动物 → 安置与建立归属 → 伙伴动物实体
```

### 3.3 用途标签

标签用于配方替代、仓储、过滤、效果匹配和 AI 判断。初始标签族包括：

- **功能：** 食用、医疗、维修、制造、学习、娱乐、礼物、防御、侦察；
- **技术：** 纯机械、本地固件、物理隔离、有线专控、只读、联网；
- **风险：** 易腐、易燃、有毒、污染、违禁、可追踪、高财富暴露；
- **物流：** 冷藏、干燥、防潮、防震、上锁、危险品；
- **归属：** 公共、个人、已分配、借用、争议、战利品、证据；
- **品质来源：** 手工、标准件、回收、旧世界、硅基制造；
- **战术：** 近战、压制、穿透、破障、隐蔽、救护、撤离；
- **社会：** 身份、纪念、宗教、文化、外交、主题交付。

标签必须来自受控词表。不能通过自由文本不断制造同义词。

### 3.4 四条资源主链映射

物品定义必须使用 `resource_chains` 表达它可能服务的资源主链：

- `survival`：食物、水、药品、住房与基本生活；
- `industry`：离线电力、零件、建材、生产和维修能力；
- `security`：武器、弹药、工事、预警和战场医疗；
- `politics`：主题交付、身份、合规、外交、声望和公共承诺。

`resource_chains` 是允许多值的用途映射，不是唯一分类。例如回收金属板可以同时属于工业链和安全链，织物可以同时属于生存链、安全链和政治链。

这项映射只说明 **潜在用途**：

- 不能因为一件物品映射到两条主链，就在两条链中重复计算库存；
- 实际占用由订单、预留、分配和承诺记录决定；
- 具体使用行为或工艺必须说明影响哪条主链及影响方式；
- 声望、信任、仇恨和合规评级等非物质状态仍是政治状态，不得伪装成库存物品；
- 只有物品被交付、展示、持有、查获或用于行动时，才通过明确效果进入政治链。

一级分类不直接决定主链，但可以提供默认建议：

| 内容方向 | 常见主链 | 说明 |
|---|---|---|
| 食品、饮水、药品、日用品 | 生存 | 战场药品可同时进入安全链 |
| 材料、零件、工具、电子用具 | 工业 | 用于武器、预警和工事时可同时进入安全链 |
| 武器、弹药、防具 | 安全 | 受控装备的持有和交易也可能进入政治链 |
| 书籍、文件、装饰、贵重品 | 政治 | 教材、工具书或储值物也可进入其他主链 |
| 家具、植物、伙伴动物 | 依据实际用途 | 不设置自动统一归属 |
| 副产物与废弃物 | 产生它的主链 | 处理负担由污染、回收或储存效果表达 |

## 4. 统一对象模型

V0.1 建议把系统拆成五层。这里描述的是设计职责，不冻结具体代码类名。

### 4.1 物品定义

描述所有同类物品共享的静态规则：

- 标识与显示名称；
- 内容分类、形态和标签；
- 基础质量、体积、堆叠和存储条件；
- 可用行为；
- 制造、拆解和维修关系；
- 可连接的效果通道；
- 默认价值、合法性和暴露特征。

### 4.2 批量库存

记录可合并物资的当前状态：

- 数量或标准批次数；
- 新鲜度、污染度或材料等级；
- 所在容器与仓储区；
- 可用、预留、分配或运输状态；
- 关联的承诺记录；
- 已知来源和归属。

只有会改变决策的状态才能阻止合并。不能因为每一批来源略有不同，就让仓库碎成大量无意义小堆。

### 4.3 独立物品实例

记录值得单独追踪的单件物品：

- 当前完整度；
- 制造品质；
- 当前持有者或部署位置；
- 分配类型与对应人物、岗位、设施或防区 ID；
- 装配模块；
- 弹药、能源或耗材状态；
- 来源、前任持有者和重要事件；
- 所有权、争议与合法状态。

普通餐具不需要成为独立实例；一把伴随人物多个月、经历过战斗并由亲属修复的步枪可以成为具名物品。

独立物品实例是“当前由谁持有”的权威来源。人物界面可以维护关键物品 ID 的派生索引以便显示，但不得复制品质、完整度、来源和分配状态，避免人物记录与物品记录互相冲突。

### 4.4 场景实体

物品部署后，由对应场景实体负责：

- 位置和占地；
- 可达性与搬运路径；
- 使用者和工作位；
- 当前运行、故障和维护状态；
- 对环境、房间或防区的影响；
- 拆卸、损坏和回收。

### 4.5 工艺与分配记录

工艺记录定义物品如何被生产、维修、拆解或转化；分配记录定义物品目前承诺给谁、哪张订单或哪个战前方案。

同一批库存不能同时被以下多个系统重复计算：

- 本周生产订单；
- 月度主题交付；
- 商队交易；
- 战前装备；
- 其他外交或任务交付。

安全储备是受保护的库存阈值，不是另一份库存，也不应与已预留或已分配状态重复计数。所有预留、分配、承诺和阈值变化必须进入供需推演。

### 4.6 承诺生命周期、撤销与冲突

库存分配状态与承诺生命周期是两套相关但不同的记录：

- **库存分配状态**回答物品当前是否仍可用于新需求；
- **承诺生命周期**回答玩家已经对谁、为了什么用途作出多强的承诺。

所有承诺使用以下最小生命周期：

| 阶段 | 是否占用库存 | 能否撤销 | 规则 |
|---|---:|---|---|
| 草拟 | 否 | 可以 | 只用于比较方案，不进入已承诺支出 |
| 预留 | 是 | 可以 | 撤销后库存返回可用，但预测和相关方案立即重算 |
| 锁定 | 是 | 有条件 | 只能承担公开代价撤销，或在规则禁止时等待结算 |
| 已履行 | 已消耗、交付或装载 | 不可直接撤销 | 只能通过新的交易、回收或返程流程取回 |
| 已取消 | 否 | 已结束 | 保留取消原因、损耗和关系后果 |

不同承诺的最小锁定规则：

| 承诺类型 | 进入预留 | 进入锁定 | 锁定前撤销 | 锁定后处理 |
|---|---|---|---|---|
| 生产或维修订单 | 玩家确认订单 | 原料开始投入或工序开始 | 返回未投入库存，预测重算 | 中止会产生已公开的在制品、材料或交接损耗 |
| 明确的主题交付 | 玩家把物品划入交付方案 | 物品提交、进入审计托管或排名冻结 | 重新计算主题预测，并显示可能失去的名次 | 按主题规则结算，不允许无代价取回 |
| 贸易或外交交付 | 双方接受具体报价 | 装载离开或合同规定的确认点 | 重新谈判或取消 | 视为违约、返运或新的交易，不瞬间返库 |
| 战前装备 | 装备方案确认 | 主意图与编组锁定 | 可以重新分配并重算两侧能力 | 只能通过战场内实际搬运、返程、遗失或缴获变化 |

月度主题不一定要求交付物品。若主题只审计仓储、设施或公共状态，系统读取审计时点的合格状态，不额外创建一份虚假的“主题库存”。只有规则明确要求提交或托管物品时，才创建主题交付承诺。

安全储备使用阈值规则：

- 安全储备不自动抢占独立库存；
- 新承诺会让预计库存跌破阈值时，确认界面必须显示缺口和后果；
- 玩家可以明确跨越阈值，但需要二次确认；
- 跨越阈值不是系统禁止，代价进入供需预测、战前风险和周末复盘。

多个需求竞争有限库存时：

1. 已履行和已锁定承诺不能被后台自动抢占；
2. 已预留需求默认按玩家确认顺序占用库存；
3. 锁定前，玩家可以主动重排或取消预留；
4. 新需求不能静默夺走既有预留；
5. 发生短缺时，受影响订单暂停并说明“缺什么、被谁占用、取消谁会改变什么”；
6. Gate 2 不实现自动最优调度，也不让 NPC 使用隐藏的不同优先级。

确认、撤销或重排承诺时，界面必须显示：

- 变化前和变化后的可用库存；
- 被影响的安全储备与供需区间；
- 会停工或失去材料的其他订单；
- 主题、贸易、人物关系或战前方案的可见后果；
- 锁定时点和此后是否仍能撤销。

## 5. 最小数据字段

### 5.1 统一定义字段

字段分为“所有定义必需”和“按形态必需”。角色实体、权利记录等非库存形态不需要伪造没有意义的重量、堆叠或仓储值；它们由对应形态的校验规则决定字段是否必需。候选库模板必须显式显示“不适用”，不能用空字符串掩盖漏填。

| 字段 | 说明 | 适用范围 |
|---|---|---|
| `id` | 稳定、唯一、与显示名称解耦的标识 | 所有定义必需 |
| `name` | 玩家可见名称 | 所有定义必需 |
| `description` | 说明用途、世界观和主要限制 | 所有定义必需 |
| `category` | 一个一级内容分类 | 所有定义必需 |
| `form` | 批量物资、独立物品、放置实体入口等 | 所有定义必需 |
| `tags` | 来自受控词表的用途与风险标签 | 所有定义必需 |
| `resource_chains` | 可能服务的生存、工业、安全或政治主链，允许多值 | 所有定义必需 |
| `availability` | 常见、有限、受控、唯一 | 所有定义必需 |
| `legal_profile` | 默认合法、受控、违禁或受硅基管辖 | 所有定义必需 |
| `exposure_profile` | 被看见、扫描、储存或交易时的暴露特征 | 所有定义必需 |
| `actions` | 使用、装备、阅读、安装、拆解等可用行为 | 所有定义必需 |
| `unit` | 件、批、箱、升、千克等玩家可理解单位 | 批量物资和可库存独立物品必需 |
| `mass` | 影响搬运与战利品携带 | 可搬运实体必需 |
| `volume` | 影响容器、仓储和车辆容量 | 可库存或可运输实体必需 |
| `stack_rule` | 是否可合并，以及哪些状态阻止合并 | 批量物资必需；其他形态不适用 |
| `storage_rule` | 常温、冷藏、干燥、上锁、危险品等 | 可库存实体必需 |
| `base_value` | 交易和财富估值起点，不等于固定售价 | 可交易、可赔偿或计入财富的对象必需 |

### 5.2 按需字段

仅在对应玩法成立时增加：

- 新鲜度和腐坏；
- 污染与净化；
- 耐久与故障；
- 电量、燃料和耗材；
- 武器弹药与模块；
- 护甲覆盖和行动负担；
- 书籍知识领域；
- 植物生长条件；
- 伙伴动物需求；
- 个人偏好、纪念和关系记录；
- 特定法律、任务或主题字段。

禁止为了“以后也许有用”给所有物品增加几十个空字段。

## 6. 数量、品质、完整度与稀有性

这些概念必须分开，不能用一个颜色等级包办。

### 6.1 数量

- 批量物资按标准单位记录；
- UI 优先显示玩家能决策的单位，例如“2 箱绷带”而非“40 条绷带”；
- 战略层弹药优先按弹匣、盒或补给批次管理；
- 战术层是否显示单发弹药，留待战斗切片验证。

### 6.2 制造品质

制造品质描述物品出厂时的工艺水平，主要受以下因素影响：

- 原料等级；
- 设施能力；
- 工具和夹具；
- 制作者技能与熟练度；
- 工艺是否完整掌握；
- 已知环境风险。

V0.1 暂建议使用四个可读等级：

1. 粗制；
2. 合格；
3. 精制；
4. 杰作。

品质等级和精确阈值均为 **待验证**。多数批量消耗品只需记录材料等级或批次合格状态，不必逐件生成品质。

### 6.3 当前完整度

完整度表示使用、损坏和老化后的状态，与制造品质无关。UI 应优先显示：

- 完好；
- 磨损；
- 需要维护；
- 严重损坏；
- 报废。

内部是否使用 0–100 连续数值，不在本文冻结。

### 6.4 可获得性

可获得性回答“有多难得到”，不回答“有多强”：

- **常见：** 可以稳定生产或交易；
- **有限：** 受季节、地点、熟练工或供应限制；
- **受控：** 受配额、身份、许可证或硅基审计约束；
- **唯一：** 有明确来源，失去后无法正常补充。

### 6.5 来源与纪念价值

来源可以影响：

- 特定人物是否愿意使用、赠送或出售；
- 原所有者与邻邦的关系；
- 战利品争议和硅基审计；
- 文化保存、主题交付和地方志；
- 交易对象愿意支付的价格。

同一把普通手枪可以因为来源而成为证物、遗物、外交筹码或仇恨标志，但不会因此凭空增加穿透力。

## 7. 库存、归属与地图物流

### 7.1 库存状态

库存分配至少区分：

- **可用：** 可以被新订单预留；
- **已预留：** 已被确认方案占用，但尚未进入不可逆工序；
- **已分配：** 已交给人物、设施、商队或防区；
- **运输中：** 已离开原仓位，尚未抵达目标；
- **争议或证据：** 物理上存在，但不能视作无后果的公共资源。

以下信息作为独立记录或覆盖层表达，不再伪装成互斥库存状态：

- 安全储备：受保护的目标阈值；
- 主题、贸易和外交承诺：关联的承诺记录及其生命周期；
- 新鲜度、污染、归属和合法性：决定能否合并或使用的批次属性。

供需推演中的“当前库存”必须能够展开分配、运输、承诺和阈值，避免玩家看到仓库有货，订单却因库存已被占用而停工。

低价值日常消耗品按聚落级消费批次管理。UI 显示计划周期内的预计总消费和缺口，不逐人逐件生成肥皂、餐具或文具使用记录；只有个人请求、短缺或特殊来源会提升为独立事件。

### 7.2 仓储规则

仓储不是纯容量数字。不同物品可能需要：

- 冷藏；
- 干燥和防潮；
- 防火隔离；
- 上锁；
- 防污染；
- 弹药与燃料分区；
- 距离使用设施足够近。

P0 不模拟完整仓储学，只保留至少一个会显著影响兑现效率的空间瓶颈。

### 7.3 搬运粒度

- 高频材料由人物搬运标准箱、捆、桶或托盘；
- 独立装备按件搬运；
- 系统自动处理同一岗位内的普通取料；
- 只有路线过长、检查站、危险区、拥堵或库存错放造成显著影响时，才进入玩家注意；
- 玩家调整仓库与设施位置应当比无限增加工作时间更有效。

### 7.4 个人物品与公共物资

物品归属可以是：

- 聚落公共；
- 人物私有；
- 临时借用；
- 工作岗位配发；
- 战前征用；
- 无主；
- 争议战利品。

征用私人纪念物、工具或武器可能提高短期可用性，同时留下关系和制度后果。普通低价值耗材不需要逐件处理所有权。

关键独立物品与人物之间使用以下合同：

- 物品实例可选记录 `holder_character_id` 和分配类型；
- 人物只维护少量关键物品 ID 的派生索引，不成为物品状态的第二权威来源；
- 借用、征用、赠送、归还和遗失通过物品实例变更，并向人物关系与记忆系统发送具名事件；
- 普通批量物资、低价值服饰和自动消费品不进入人物永久持有列表；
- 对某类武器、工具或设备的熟悉程度属于人物的专业经验或岗位资格，不绑定某一件实例。

## 8. 物品获得与流失

### 8.1 获得渠道

- 聚落生产；
- 种植、采集和养殖；
- 维修、翻新和拆解；
- 贸易、配额与合法采购；
- 礼物、继承和人物自带；
- 废墟回收与外出探索；
- 自由意志日战利品；
- 任务、外交和主题相关交付；
- 硅基或邻邦提供的受控设备。

不同来源必须有不同代价。不能让劫掠同时成为最省时间、最省材料且没有后果的获得方式。

### 8.2 流失渠道

- 日常消费；
- 腐坏、污染和自然老化；
- 使用磨损与战斗损坏；
- 维修消耗；
- 生产副产物和失败；
- 贸易、赠送、进贡和主题交付；
- 盗窃、没收、遗失和放弃；
- 建筑损毁与撤离时无法携带；
- 人物死亡、失联或被俘时随身物品暂时离开库存。

### 8.3 战利品规则

战利品不是战斗胜利后的无限奖励：

- 需要在有限时间内识别、搬运和撤离；
- 伤员、俘虏和重装备共享运力；
- 来源不明的物品可能受污染、设有追踪或存在所有权争议；
- 高价值库存会提高财富暴露和次月被针对程度；
- 工艺样本可以提供研究或拆解机会，但不等于立即复制；
- 硅基设施和受保护资产不能成为常规刷取来源。

## 9. 制造系统

### 9.1 基础关系

制造不是“材料足够后等待固定进度条”，而是以下条件共同兑现的过程：

```text
可接受输入
+ 工作设施
+ 必要工具
+ 人物有效时间
+ 岗位资格与工艺知识
+ 能源和环境条件
→ 成品产量区间
+ 品质区间
+ 副产物
+ 已知失败风险
```

### 9.2 生产队列与周计划

两者职责必须分开：

- **生产队列：** 决定设施要生产、维修或拆解什么；
- **周计划：** 决定哪些人物投入多少时间；
- **人物自主执行：** 处理普通取料、设施操作和成品入库；
- **供需推演：** 汇总原料、承诺、预计产出、损耗和期末状态；
- **地图：** 决定人物能否按计划及时取料、加工和入库。

玩家不需要逐件指定“由谁拿哪块钢板”，但可以指定重要订单的负责人、品质目标、材料策略或优先级。

### 9.3 订单类型

V0.1 记录以下候选订单意图，但分阶段引入：

| 订单 | 用途 | 最早评估阶段 |
|---|---|---|
| 制作固定数量 | 一次性需求、任务或战前准备 | Gate 2 |
| 修复至目标状态 | 保持关键设备和装备可用 | Gate 2 以后 |
| 紧急抢修 | 接受更高损耗或较低品质换取速度 | Gate 2 以后 |
| 拆解指定物品 | 回收材料、分析工艺或清除风险 | Gate 3 |
| 翻新 | 以材料和时间恢复旧物价值 | Gate 4 |
| 维持库存区间 | 高频食品、药品、零件和弹药的自动补货 | Gate 4 后单独评估 |

当前 Gate 1 不实现通用订单类型。Gate 2 只用“制作固定数量”手动模拟共享瓶颈；NPC 也使用固定、公开的投入，不运行隐藏自动补货。

“维持库存区间”不是普通订单的简单变体。它至少需要最小/最大阈值、检查频率、自动订单生成、产能冲突、手动订单优先级和暂停条件。只有固定数量订单已经能清楚表达机会成本后，才能单独验证自动补货是否减少无意义操作而没有替玩家消解取舍。

### 9.4 输入方式

工艺可以要求：

- 精确物品；
- 某类标签材料；
- 若干允许替代的材料；
- 最低材料等级；
- 不允许被替代的关键零件。

替代不能只改成本。它应影响可读结果，例如：

- 木制枪托更易制造，但受潮后可靠性下降；
- 回收金属板可以用于路障，但不适合高质量护甲；
- 清洁布可以制作绷带，污染织物必须先消毒；
- 高容量联网电池性能更好，但增加锁定和追踪风险。

### 9.5 计划产出区间

沿用周计划切片的基础关系：

```text
计划产出区间
  = 设施基础能力
  × 有效活动块
  × 人物执行效率区间
  × 原料与工具条件
  × 设施状态区间
  × 环境与空间兑现区间
```

每个主要修正必须能展开为玩家可读原因。未知事件不能提前偷偷压低区间；事件发生后应先公开新信息，再更新预测。

### 9.6 品质结果

品质结果主要取决于：

```text
材料能力
+ 设施与工具上限
+ 制作者技能和熟练度
+ 已掌握的工艺
- 已知赶工、替代和环境风险
```

高技能人物不能用泥土制造高质量轴承；高端设施也不能让未经训练的人稳定完成复杂手术器械。

品质区间在订单确认前可见。赶工、材料替代和低维护设施带来的风险必须公开。

#### 9.6.1 人物能力与品质职责

人物规则已经定义“广义技能 + 属性 + 专业经验或资格 + 工具设施 + 当前状态与认同”的执行框架。物品与制造系统不另建第二套人物能力。

Gate 2 前先冻结输入职责，不冻结具体技能阈值：

| 输入 | 在制造中的初步职责 |
|---|---|
| 广义技能 | 影响基础产量、耗时和执行稳定性 |
| 相关基础属性 | 影响精细操作、体力负担和风险下限 |
| 专业经验或岗位资格 | 解锁特定工艺，并可能提高品质上限 |
| 工具与设施能力 | 决定可执行工艺和可达品质上限 |
| 材料能力 | 决定成品物理性能和最高可能品质 |
| 当前身体、压力与认同 | 扩大或缩小产量、耗时和品质区间 |
| 赶工、替代和环境风险 | 形成订单确认前可见的负修正 |

每张工艺需要声明：

- 最低可执行资格；
- 使用的广义技能；
- 可以提高品质上限的专业经验；
- 工具、设施和材料分别限制什么；
- 缺少资格时是禁止工艺、降低品质上限，还是扩大失败风险。

原型必须能区分材料瓶颈、设施瓶颈和熟练人物时间瓶颈。具体阈值、曲线和品质概率仍由对应 Gate 的固定场景验证。

### 9.7 副产物与失败

制造可能产生：

- 可回收边角料；
- 污水、废油、烟尘或有毒残留；
- 废品和次品；
- 弹壳、包装和污染耗材；
- 需要额外处理的危险物。

失败优先表现为：

- 延误；
- 材料损耗；
- 品质下降；
- 设施磨损；
- 可解释的工伤风险。

不能使用与玩家已知条件无关的突然爆炸制造戏剧。

废弃物优先使用简化模型：

- 污水、烟尘和一般污染汇总为处理负担或风险值，不逐件进入仓库；
- 可回收边角料、弹壳、废油和稀有电子废料继续使用批量库存；
- 只有会被搬运、储存、交易、回收或造成明确空间风险的废弃物才生成物品；
- Gate 1 不实现通用废弃物库存。

## 10. 维修、拆解与维护

### 10.1 维修

维修至少需要：

- 故障或损坏诊断；
- 兼容材料或零部件；
- 工具和设施；
- 具备资格的人物时间；
- 可接受的停机窗口。

维修目标可以是：

- 恢复运行；
- 恢复至安全状态；
- 完整翻新；
- 临时旁路。

临时旁路能快速恢复功能，但可能扩大预测区间、提高耗能、降低品质上限或增加下周故障风险。

### 10.2 预防维护

维护不是定时点击税。它应当：

- 进入基础周计划；
- 在设施稳定时由人物自动执行；
- 只有资源短缺、人物调离或风险跨线时才要求玩家决定；
- 与生产、学习、主题冲刺和军备制造争夺时间；
- 缩小产能预测区间，而不只延缓一条隐藏耐久条。

### 10.3 拆解

拆解可能提供：

- 基础材料；
- 可复用零部件；
- 工艺样本；
- 污染和危险副产物；
- 对来源、追踪或故障原因的线索。

回收率受物品状态、拆解设施、人物能力和时间投入影响。拆解不能无损返还所有原料，否则制造选择没有成本。

### 10.4 维护标准

生产队列可以设置：

- 关键设施最低安全状态；
- 普通工具的集中维护周期；
- 武器和护甲的战前整备标准；
- 低优先级物品的报废阈值。

玩家不应被迫逐件检查几十把普通工具。

---

## 11. 工艺知识、图纸与学习

获得图纸不等于人物立刻掌握工艺。完整解锁由以下部分组成：

```text
知识来源
+ 可阅读或可解析条件
+ 学习时间
+ 基础技能或导师
+ 可用设施与练习材料
→ 岗位资格、工艺熟练度或问题解决方式
```

知识来源包括：

- 纸质手册；
- 只读存储；
- 本地离线终端；
- 拆解样本；
- 具备经验的人物；
- 邻邦培训或工艺交换；
- 反复维修形成的实践知识。

书籍和数据载体因此可以同时用于：

- 人物学习；
- 文化保存；
- 主题交付；
- 外交交换；
- 证明某项工艺来源；
- 纪念与人物事件。

联网数据库可能更完整、更高效，但伴随访问控制、锁定、追踪或征用风险。

## 13. 武器系统

### 13.1 定位

武器用于完成防守、破障、压制、撤离和有限掠夺目标，不以清空地图或追求击杀数为唯一目的。

武器不能只比较单一伤害值。至少需要表达：

- 有效距离；
- 命中与操控；
- 伤害方式；
- 穿透能力；
- 压制或威慑；
- 噪声与暴露；
- 可靠性；
- 弹药和耗材；
- 携行负担；
- 维修条件。

### 13.2 有限模块化

完整游戏可以让武器由基础平台和少量有明确取舍的模块构成，例如瞄具、握持、供弹或破障方向。

有限模块化是方向，不是 Gate 3 已冻结合同。模块数量、类型和是否值得存在，必须在最小武器差异已经通过战术切片后决定。若进入实现，模块必须改变使用方式、物流或风险，不提供大量随机微小加成，也不能生成“伤害 +2%、命中 +1%”式词条池。

### 13.3 弹药

- 不同弹药应在穿透、停止作用、噪声、制造难度或目标限制上有意义；
- 战略层优先管理弹药批、弹匣和补给箱；
- 训练消耗真实弹药或替代训练资源；
- 受潮、混装和低质量装药会影响可靠性；
- 自由意志日结束后的未使用弹药仍有回收、遗失和争议；
- 具体口径数量在战斗切片前不冻结。

### 13.4 人物适配

武器效果还取决于：

- 人物训练和熟悉度；
- 伤势与体力；
- 当前情绪和创伤；
- 对使用方式的立场；
- 携行与撤离任务；
- 队伍通信和交战教条。

人物不因“等级不足”被绝对禁止使用普通武器，但可能出现低效、故障处理困难、误伤风险或拒绝执行。

---

## 14. 防具、服饰与携行

### 14.1 防具属性

防具至少表达：

- 覆盖部位；
- 穿透防护；
- 钝击吸收；
- 行动与工作负担；
- 炎热、潮湿或寒冷负担；
- 当前完整度；
- 维修材料和设施；
- 穿脱与撤离成本。

更重的防具不应在所有场景都更优。远征、搬运、伏击、守墙、医疗和撤离对装备的需求不同。

### 14.2 服饰价值

服饰可以影响：

- 气候和环境适应；
- 工作安全和卫生；
- 伤口污染；
- 身份、谈判和邻邦识别；
- 人物偏好与尊严；
- 伪装、可见度和检查站风险。

服饰不能全部沦为护甲的低级前置品。

### 14.3 最小装备验证范围

完整装备槽尚未冻结。Gate 3 战术切片只验证以下最小集合：

- 主武器；
- 身体防护；
- 一项任务工具或战术用品；
- 弹药和医疗补给，两者是资源类别，不预设为装备槽；
- 携行上限。

只有当战术测试证明有必要时，才扩展头部、足部、背包、饰品和多层服饰。

### 14.4 战前装备承诺

战前分配必须进入以下计算：

- 出击队和留守队预计能力；
- 弹药与医疗余量；
- 携带战利品和伤员的剩余运力；
- 后台防区压力；
- 人物拒绝或低效风险；
- 未装备人员与设施的剩余物资。

锁定后不能在主副战场之间瞬间传送装备。

---

## 15. 药品与医疗用品

药品不采用“喝下立即恢复生命值”的通用药水模型。医疗效果取决于：

- 伤病类型；
- 使用时机；
- 药品和耗材是否匹配；
- 医疗人员能力；
- 诊所、卫生和工具条件；
- 患者状态与后续休养。

医疗用品可以分为：

- 日常卫生与预防；
- 基础包扎与消毒；
- 感染与疾病治疗；
- 止血与创伤处理；
- 固定、缝合和手术耗材；
- 疼痛、镇静和长期恢复；
- 战场救护包。

同一批织物、酒精和药物在日常医疗、主题准备和自由意志日救护之间形成竞争。

---

## 16. 工具与电子用具

### 16.1 工具

工具主要提供：

- 允许执行某项工艺；
- 提高设施能力上限；
- 缩短人物有效时间；
- 降低材料损耗；
- 缩小品质或产量区间；
- 降低工伤和故障风险。

工具不应只提供无条件“效率 +10%”。缺少工具、工具磨损和使用者不熟悉时应产生不同结果。

### 16.2 电子用具

电子用具必须遵守离线技术原则，并区分：

| 技术状态 | 优势 | 代价 |
|---|---|---|
| 纯机械或模拟 | 可修、难锁定、低依赖 | 精度和自动化有限 |
| 本地固件 | 效率较高、可离线运行 | 需要兼容零件和技术人员 |
| 物理隔离或有线专控 | 风险可管理、功能稳定 | 布线、距离和维护成本 |
| 只读设备 | 适合档案和诊断 | 更新困难、功能有限 |
| 联网设备 | 数据完整、自动化高 | 审计、锁定、追踪和征用风险 |

高技术设备不是线性升级。聚落可能主动选择较笨重但可控的离线方案。

---

## 17. 书籍、家具、日用品与贵重品

### 17.1 书籍与数据载体

用途包括：

- 支撑学习和岗位资格；
- 保存工艺与历史；
- 作为人物私人物品；
- 触发社交、教育和地方志事件；
- 用于文化类主题或外交交换；
- 提供拆解样本无法说明的安全规范。

书籍存放在仓库里不会自动提升全体技能。需要阅读条件、学习时间和可理解的语言或格式。

### 17.2 家具

家具通过实际放置产生价值：

- 床和寝具影响恢复；
- 桌椅和公共空间支持社交；
- 储物家具改变取料距离和安全；
- 工作家具提供工位或工具条件；
- 卫生家具影响污染与疾病；
- 展示家具承载纪念、身份和财富暴露。

家具不应只是房间美观分数。

### 17.3 日常用品

肥皂、卫生用品、容器、餐具、缝补用品和文具用于表达聚落是否仍保有正常生活。它们可以影响：

- 卫生与疾病；
- 物资保存；
- 工作损耗；
- 人物请求和尊严；
- 贸易与主题交付；
- 关系事件。

系统应按聚落级消费批次处理普通用品，避免逐人逐件补充。

### 17.4 装饰、乐器和珠宝

这些物品可以承担：

- 礼物与关系确认；
- 纪念死者和保存家庭历史；
- 建立聚落、派系或宗教身份；
- 娱乐和社交活动；
- 文化主题交付；
- 小体积财富储存；
- 伪装、身份识别或秘密信息载体。

它们也可能提高盗窃风险、内部争议和财富暴露。价值来自用途和来源，不来自“装备后魅力 +5”的统一饰品槽。

---

## 18. 植物与伙伴动物

### 18.1 植物

植物进入世界后不再是普通物品。最小生命周期为：

```text
种源物品
→ 播种或移栽任务
→ 生长中的植物实体
→ 成熟、患病或死亡
→ 收获物、副产物和新种源
```

植物可以分为：

- 食用作物；
- 药用植物；
- 纤维与工业作物；
- 香料和特殊加工原料；
- 饲料作物；
- 观赏与纪念植物；
- 野生采集物。

生长受到季节、水、肥料、土壤、设施、人物时间和地图物流影响。当前两周切片只需要化肥影响粮食产量，不实现完整植物系统。

### 18.2 伙伴与役用动物

动物不是可堆叠宠物道具；一旦进入聚落，它们属于角色实体，而不是库存堆叠。V0.1 只保留这项形态边界和内容候选，不冻结需求、信任、训练、繁殖、伤病或任务接受系统。

候选作用包括：

- 陪伴和缓解孤立；
- 预警和守卫；
- 捕鼠与害物控制；
- 信使与通信；
- 轻型搬运；
- 蛋、奶、纤维等有限产出；
- 搜救和追踪。

伙伴动物的价值不能只表现为生产效率。详细的个体需求、人物关系、训练和损失规则在 Gate 4 后单独立项；Gate 1–4 不增加伙伴动物运行时、UI 或测试范围。

---

## 19. 稀有物品与特殊物品

稀有物品不建立单独的高强度装备阶梯。其价值可以来自：

- 无法稳定复制的旧世界工艺；
- 受控或已经停产的零部件；
- 特定人物、聚落或历史事件的来源；
- 具有法律或身份效力的凭证；
- 能提供工艺研究的样本；
- 能改变外交判断的证据；
- 高效但可能被远程锁定的联网设备；
- 独特文化和纪念意义。

候选示例：

- 未联网的旧世界精密机床控制器；
- 已失效但仍有法律争议的身份芯片；
- 某邻邦创始人的机械表；
- 完整的外科器械箱；
- 硅基制造、状态未知的高密度电池；
- 记录自由意志日违规行为的只读存储；
- 无法复制的种质样本；
- 一件工艺优秀但归属有争议的武器。

稀有物品应当制造决定，而不是只制造更高售价。

---

## 20. 效果通道

物品效果只能通过明确的使用情境生效。

### 20.1 允许的效果通道

- **作为输入：** 改变工艺产量、品质、损耗或风险；
- **被人物使用：** 满足需求、治疗、学习、娱乐或工作；
- **被装备：** 改变战术、劳动安全、携行或环境适应；
- **被放置：** 改变空间、仓储、工位、卫生或社交条件；
- **被分配：** 改变战前编组、岗位和防区能力；
- **被交付：** 影响贸易、主题、外交或法律承诺；
- **被展示或纪念：** 影响特定人物、关系和地方认同；
- **被储存：** 产生腐坏、危险、维护或财富暴露。

### 20.2 禁止的效果模式

- 仅因存在于仓库就让全体获得无条件增益；
- 同类物品无限叠加全局百分比；
- 未经使用过程，图纸直接解锁人物技能；
- 稀有度颜色直接乘算全部属性；
- 装饰、书籍和珠宝统一转化为抽象心情分；
- 玩家无法追溯来源的后台随机增减。

---

## 21. 界面与信息表达

本节只冻结物品界面必须回答的信息问题和因果可见性，不冻结布局、控件数量、默认展开层级或操作步骤。具体交互必须在对应 Gate 的原型中验证。

### 21.1 物品详情

物品详情采用渐进披露，首屏优先回答：

1. 这是什么；
2. 现在能做什么；
3. 为什么此刻重要；
4. 当前在哪里、由谁持有或被什么订单占用；
5. 使用后会改变哪条预测或承诺。

展开后再显示：

- 制造与拆解来源；
- 品质、完整度和维护；
- 存储与物流；
- 合法性、来源和暴露；
- 详细效果与历史记录。

### 21.2 库存界面

默认视图不按字母排列全部物品，而应支持：

- 当前短缺；
- 已承诺和即将消耗；
- 生产停工所缺；
- 需要维护；
- 战前未分配；
- 易腐、危险和暴露；
- 人物私有与争议物品；
- 分类、地点和标签筛选。

### 21.3 制造界面

每张订单至少显示：

- 预计完成区间；
- 预计产量和品质区间；
- 主要人物、设施和工具条件；
- 已有、预留和缺少的输入；
- 会跨越哪条安全储备；
- 对其他订单和供需状态的主要影响；
- 当前最大的已知风险。

点击缺少的材料，应能追溯：

```text
为什么缺
→ 哪些库存已经被承诺
→ 可以从哪里生产、拆解、交易或回收
→ 改动后哪些预测会变化
```

### 21.4 装备界面

战前装备界面优先比较任务适配，而不是总战力：

- 人物是否熟悉；
- 弹药和维护是否可持续；
- 防护与行动负担；
- 医疗与撤离能力；
- 出击与留守之间的物资分配；
- 目标、路线和交战教条是否匹配；
- 装备被带走后家园还剩什么。

## 22. 经济与平衡原则

### 22.1 每件物品必须回答的问题

正式内容进入运行时前，应回答：

1. 玩家为什么想获得它；
2. 它与哪件物品、人物时间或设施竞争；
3. 它在哪些情境下不是最优；
4. 它如何消耗、损坏、转移或离开经济；
5. 它是否连接人物、主题、战斗或地图；
6. 若删除它，是否会失去独特决策。

若答案只是“比上一件数值高一点”，应合并或删除。

### 22.2 资源来源与消耗

稳定经济需要同时存在：

- 可预测的基础产出；
- 有限但可计划的进口和回收；
- 消费、腐坏和维修；
- 建设与生产承诺；
- 战斗损失和撤离限制；
- 贸易、礼物、主题和进贡；
- 高库存带来的仓储与暴露代价。

### 22.3 避免囤积成为唯一解

显著过剩可能造成：

- 腐坏与品质下降；
- 需要更多仓储和守卫；
- 危险品事故风险；
- 主题审计或硅基关注；
- 邻邦判断玩家值得攻击；
- 人物对分配不公的争议；
- 资金和材料被锁在低周转库存中。

但系统不能把所有储备都惩罚掉。安全库存仍是合理策略，问题在于过量、暴露和机会成本。

### 22.4 价格

交易价格不是固定商店价。它可以受以下因素影响：

- 对方需求和库存；
- 关系、信誉和仇恨；
- 路线和检查风险；
- 合法性与来源；
- 品质、完整度和保质期；
- 月度主题；
- 自由意志日前后的时间压力。

P0 只需少量透明修正，不做复杂动态市场。

## 23. 候选内容库规模

完整候选库建议先以约 **220 项** 为内容规划目标。该数字是覆盖检查工具，不是运行时承诺。“最早受限样本”只表示某一组可以在何时出现极少量验证对象，不表示整组获得导入授权。

| 内容组 | 候选数量 | 最早受限样本 |
|---|---:|---|
| 材料、能源与副产物 | 36 | Gate 1 仅化肥；Gate 2 选择一项共享材料 |
| 零部件、工具与电子用具 | 28 | Gate 2 选择共享瓶颈所需样本 |
| 食品、饮料、药品与医疗用品 | 28 | Gate 2 使用少量食品；Gate 3 使用少量医疗品 |
| 武器与弹药 | 24 | Gate 3 最小战术样本 |
| 防具与服饰 | 24 | Gate 3 仅身体防护样本 |
| 书籍、数据载体、文件与凭证 | 16 | Post-Gate 4 |
| 家具、日用品、装饰与珠宝 | 32 | Post-Gate 4 |
| 植物与种源 | 12 | Post-Gate 4；Gate 1 不生成植物实体 |
| 伙伴与役用动物 | 8 | Post-Gate 4 |
| 稀有与特殊物品 | 12 | Gate 3–4 最多少量工艺或战利品样本 |
| **合计** | **220** | **任何 Gate 均不整组导入** |

内容库中的每项只代表候选设计。进入运行时前还需通过：

- 是否服务当前阶段；
- 是否依赖尚未验证的系统；
- 是否与既有物品形成独特决策；
- 是否进入至少一条产业链；
- 是否具有获得与消耗路径；
- 是否有合理存储、物流和价值；
- 是否能被 UI 清楚解释。

## 24. 分阶段验证

### 24.1 当前 Gate 1：化肥样本

只验证：

- 化肥具有有限库存；
- 可以被本周农田计划使用或保留；
- 使用后明确改变粮食产量区间；
- 预测说明化肥是否已经预留、是否按时送达；
- 水泵故障、人物和空间瓶颈仍能改变实际结果；
- 周末复盘能说明计划值与实际值为何不同。

不验证：

- 通用背包；
- 多级品质；
- 复杂制造配方；
- 装备和耐久；
- 完整植物实体；
- 交易、战利品和稀有物品。

### 24.2 Gate 2：主题—军备共享瓶颈

Gate 1 通过后，选择一项共享资源或设施时间，验证：

- 民生、主题与军备能否争夺同一瓶颈；
- 玩家是否能在确认订单前看见机会成本；
- 预留和安全储备是否被正确计入；
- 获得主题第一是否真的牺牲至少一档安全能力；
- NPC 是否遵守同一公开资源逻辑。

不以扩大物品数量掩盖共享瓶颈设计失败。

### 24.3 Gate 3：最小装备与战术物资

战术切片先限制为少量差异清楚的：

- 主武器；
- 身体防护；
- 一项任务工具或战术用品；
- 弹药和医疗补给，两者是资源类别，不预设为装备槽；
- 携行上限。

本清单与 §14.3 一致，不代表已经冻结完整装备槽。

验证：

- 装备差异是否改变任务方案；
- 出击与留守是否形成可解释分配；
- 弹药、医疗和携行是否限制收益；
- 装备损坏与战后维修是否连接日常经营；
- 玩家是否能解释后台防线为什么缺少某项能力。

### 24.4 Gate 4：三个月整合

三个月原型只导入闭环必需的物品子集，并遵守：

- 资源仍为四种核心汇总；
- 建筑不超过六种；
- 主题只有少量；
- 不制作完整科技树；
- 不导入完整 220 项候选库；
- 物品必须服务主题机会成本、战前承诺、战利品限制或跨月恢复。

### 24.5 完整内容阶段

只有 Gate 1–4 的证据证明核心循环成立后，才按产业链扩写候选库、冻结正式内容批次并进入大规模数据制作。

## 25. 示例定义

以下示例用于检查字段关系，不是最终运行时格式。三个示例统一使用：

- `resource_chains`：潜在主链映射；
- `effects`：只有在明确使用情境中才生效的效果；
- `usage_constraints`：材料、工艺或任务限制；
- `risks`：已知风险；
- `example_commitment`：仅用于演示承诺生命周期，不属于物品静态定义。

为保持示例简短，未重复列出质量、体积、基础价值等所有必需字段；这些省略不表示字段可选。

### 25.1 化肥

```yaml
id: item.agriculture.compound_fertilizer
name: 复合化肥
category: 材料
form: 批量物资
tags:
  - 农业投入
  - 化学品
  - 防潮
resource_chains:
  - survival
  - politics
unit: 袋
stack_rule: 同批次且污染状态一致时可合并
storage_rule:
  - 干燥
  - 远离食品
availability: 有限
actions:
  - 预留给农田计划
  - 交易
  - 交付
effects:
  - channel: 作为输入
    target: 本周农田产量区间
    resource_chain: survival
usage_constraints:
  - 只有按时送到农田并完成施用才产生效果
risks:
  - 未按时送到农田则不生效
  - 水泵故障仍会降低实际产量
example_commitment:
  type: 生产订单
  state: 预留
  withdrawal: 锁定前撤销会返还化肥，并立即扩大粮食缺口预测
```

### 25.2 回收金属板

```yaml
id: item.material.reclaimed_steel_plate
name: 回收金属板
category: 材料
form: 批量物资
tags:
  - 金属
  - 回收

resource_chains:

unit: 捆

  - channel: 作为输入

    resource_chain: security
usage_constraints:
  - 精密轴承
  - 高质量枪管
risks:
  - 用于安全链时会减少工业维修储备
```

### 25.3 争议来源的步枪


## 26. 验证问题

后续原型和评审至少回答：

1. 玩家能否理解“有库存”和“可用于新订单”之间的差别；
2. 点击短缺能否追溯到人物、设施、原料、承诺和地图路径；
3. 共享材料是否真的让民生、主题和军备互相排挤；
4. 品质、完整度、可获得性和来源是否容易区分；
5. 维修是否是可计划的风险管理，而不是逐件点击税；
6. 战前装备是否改变意图和撤离方案，而不是只提高总战力；
7. 书籍、服饰、家具、日用品和贵重品是否产生非战斗决策；
8. 联网设备的效率与依赖风险是否形成真实选择；
9. 战利品携带、来源和暴露是否阻止“胜利后搬空地图”；
10. 候选物品库是否可以在不增加新系统的前提下持续扩写。

## 27. 待定问题

以下问题不在 V0.1 冻结：

1. 战略层与战术层弹药粒度；
2. 人体部位、伤害和护甲覆盖模型；
3. 完整装备槽数量；
4. 品质与完整度的内部数值表达；
5. 贸易计价和聚落财富计算；
6. 受控、违禁与可追踪物品的具体执法规则；
7. 网络设备被锁定或征用的交互频率；
8. 植物季节、生长周期和基因差异；
9. 伙伴动物繁殖、训练和战斗参与边界；
10. 个人所有权与战时征用的制度规则；
11. 物品命名、纪念和地方志记录的触发条件；
12. 正式候选库的第一批内容和冻结顺序。

这些问题应当在对应玩法即将进入下一 Gate 时解决，不能提前转化为大规模实现。

## 2. 关键修正结果

### 2.1 承诺生命周期

新增：

```text
草拟
→ 预留
→ 锁定
→ 已履行 / 已取消
```

生产、维修、主题交付、贸易外交和战前装备分别定义：

- 何时占用库存；
- 何时进入锁定；
- 锁定前能否撤销；
- 锁定后如何处理；
- 撤销对预测、关系、主题和人物记忆的影响。

安全储备改为受保护阈值，不再作为重复库存状态。

### 2.2 四条资源主链

所有物品定义增加多值 `resource_chains`：

- `survival`
- `industry`
- `security`
- `politics`

多值只表达潜在用途，实际占用仍由订单和承诺决定，同一库存不会因跨链标签重复计算。

### 2.3 人物与物品单一权威

- 独立物品实例是持有人、品质、完整度、来源和分配状态的唯一权威；
- 人物侧只保存关键物品 ID 的派生索引；
- 武器、工具和设备熟悉度进入专业经验或岗位资格；
- 借用、征用、赠送、归还、遗失和损毁通过物品事件进入人物记忆。

### 2.4 制造品质接口

冻结了职责，不冻结数值：

| 输入 | 职责 |
|---|---|
| 广义技能 | 产量、耗时和稳定性 |
| 基础属性 | 精细操作、体力和风险 |
| 专业经验或资格 | 解锁工艺、提高品质上限 |
| 工具与设施 | 决定可执行工艺和可达上限 |
| 材料能力 | 决定成品物理上限 |
| 当前状态与认同 | 调整结果区间 |
| 赶工、替代和环境 | 形成公开负修正 |

### 2.5 阶段边界

- Gate 1：仍只有化肥样本；
- Gate 2：只用固定数量订单测试共享瓶颈；
- Gate 3：验证统一的最小装备集合；
- Gate 4：仍不导入完整候选库；
- 自动补货、伙伴动物详细规则、完整模块系统和大规模内容制作继续延后。

## 3. 复审过程中新增问题

### 3.1 字段对非库存形态适用性不清

完整复审新增一个 P2：

- 原“所有物品必需字段”会让伙伴动物、权利记录等形态被迫填写无意义的堆叠或仓储字段。

修正：

- 改为“统一定义字段”；
- 增加适用范围列；
- 区分所有定义必需与按形态必需；
- 候选模板使用“不适用”，不用空字符串掩盖漏填。

窄范围复审结论：

```text
OLD_NEW_P2=CLOSED
NEW_P0=0
NEW_P1=0
NEW_P2=0
REVIEW_PASS
```

### 3.2 Gate 3 最小装备清单不一致

当前快照复审发现：

- §14.3 与 §24.3 对弹药、医疗和携行上限的列表不同。

修正后两节统一为：

- 主武器；
- 身体防护；
- 一项任务工具或战术用品；
- 弹药和医疗补给，两者是资源类别，不预设为装备槽；
- 携行上限。

### 3.3 未定义的家庭消费单元

当前快照复审发现“家庭或聚落级消费批次”依赖尚未定义的家庭管理单元。

修正为：

- 低价值日用品统一按聚落级消费批次处理；
- 只有个人请求、短缺或特殊来源才提升为独立事件。

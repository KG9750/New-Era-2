## 1. P1：必须关闭的严重缺口

### P1-1：履历到属性、技能和专业经验的推导合同不闭合

**证据：**

- `character-generation-rules-v0.1.md:323–346` 给出了“中值 5 + 各类修正”的骨架；
- `character-generation-rules-v0.1.md:356–390` 定义了八项技能和专业经验；
- `character-generation-rules-v0.1.md:401–412` 说明最终结果由属性、技能、资格和状态共同决定，但明确把公式留给后续；
- `character-generation-rules-v0.1.md:521–543` 又要求生成器从履历推导上述数据，并禁止先随机属性再倒写传记。

**问题：**

当前规则没有定义履历节点如何产生可复现的属性修正、技能经验和资格。手工作者可以凭直觉填写，但不同作者无法保持一致，运行时补充生成器也无法按“同一规则”工作。

这不是 P0：文档明确把具体数值放到后续规格，且 Gate 1 不实现该生成器。但它会阻塞阶段 B 的 50 人批量内容一致性和阶段 C 的运行时生成。

**关闭条件：**

1. 建立结构化履历节点目录；
2. 每个节点定义适用年龄、前置条件、属性修正、技能经验、资格、关系或人格输出；
3. 定义固定种子微调的范围和分布；
4. 给出至少三条完整推导样例；
5. 明确哪些结果由程序计算，哪些结果需要内容审核者确认。

**截止点：** 编写 50 人正式库之前。

---

### P1-2：单人人物校验与开局团队校验混在同一阶段

**证据：**

- `character-generation-rules-v0.1.md:545–556` 把“生成结果会让标准开局失去基础生存能力”列为人物生成失败；
- `character-generation-rules-v0.1.md:562–576` 才定义四人组合规则；
- `character-generation-rules-v0.1.md:570` 使用“接近覆盖生产、医疗、防卫和交涉”；
- `character-generation-rules-v0.1.md:601` 允许标准难度阻止完全无法运行的组合。

**问题：**

单个人物生成时无法判断尚未组成的四人团队是否具备基础生存能力。同时，“接近覆盖”“基础循环”“完全无法运行”都没有操作性阈值。

**关闭条件：**

1. 将校验分为 `CharacterValidation`、`PartyValidation` 和 `RuntimeValidation`；
2. 从单人物失败列表移除团队生存判断；
3. 为标准开局列出必须可完成的基础活动；
4. 为生产、医疗、防卫、交涉定义最低团队能力阈值；
5. 定义“单点失效”的判定方式；
6. 明确极端组合只在挑战模式开放。

**截止点：** 开局候选池与四人选择实现之前。

---

### P1-3：人物死亡后的补员规则没有闭合

**证据：**

- `character-generation-rules-v0.1.md:78–87` 确认两月阶段最多一次加入机会，但把死亡后的补员留作待验证；
- `character-generation-rules-v0.1.md:605–628` 规定标准与特殊剧情加入原则上共享阶段额度；
- `character-generation-rules-v0.1.md:832–840` 再次把紧急补员列为待解决问题；
- `concept-design-v0.4.md:735–755` 允许玩家直接控制的主战场发生具名人物死亡。

**问题：**

开局仅 4 人。若在早期直接控制战场失去成员，玩家可能长期以 3 人甚至更少人口运行，但现有规则没有确定补员是否占用阶段机会、等待多久、承担什么代价。

这不阻塞没有战斗的 Gate 1，但会影响第一个允许具名人物死亡的战斗切片。

**关闭条件：**

1. 确定死亡补员是否占用两月阶段加入额度；
2. 定义紧急补员的最早触发时间、代价和候选质量；
3. 防止玩家通过故意送死刷新更优人物；
4. 明确低于维持人口阈值时的失败保护或软败路径；
5. 将规则纳入战斗切片验收。

**截止点：** 第一个允许具名人物死亡的战斗原型之前。

---

### P1-4：硬校验混合了机器校验、人工内容审查和运行时验证

**证据：**

`character-generation-rules-v0.1.md:739–769` 把以下不同性质的判断放在同一“硬校验/软校验”列表：

- 可直接机器判断：人口上限、稳定 ID、固定种子、完全重复指纹；
- 依赖结构化数据后才可判断：年龄与履历、资格来源、双向关系；
- 依赖人工语义判断：姓名与文化冲突、属性极值是否被履历充分解释；
- 依赖 UI 与运行时事件：红线是否公开并触发重大抗命；
- 缺少阈值的内容警告：创伤过度集中、履历转折高度相似。

**问题：**

“硬校验”当前既可能指构建时 validator、内容审稿人、运行时 assertion，也可能指玩家测试。实现者无法确定失败发生在哪个阶段、由谁判定、是否阻止构建。

**关闭条件：**

为每项校验补充：

- `Executor`：机器 / 内容审核 / 运行时 / 玩家测试；
- `Phase`：人物生成 / 团队组合 / 聚落分配 / UI / 存档加载；
- `Predicate`：结构化判断条件；
- `Severity`：阻止构建 / 阻止入库 / 警告 / 仅记录；
- `Evidence`：失败时必须输出的字段和来源。

**截止点：** 编写内容校验器或批量录入 50 人之前。

---

### P1-5：NPC 简化模拟的首次生成、完整化和关系端点合同缺失

**证据：**

- `character-generation-rules-v0.1.md:447–454` 要求亲属、债务、血仇和救命关系存在另一端；
- `character-generation-rules-v0.1.md:632–660` 允许 NPC 使用简化模拟，并要求重新进入完整模拟时不得重掷属性、人格或履历；
- `character-generation-rules-v0.1.md:650–658` 要求简化模拟保留具名列表、核心能力、关系和状态；
- `character-generation-rules-v0.1.md:771–779` 要求相同输入产生相同人物内容。

**问题：**

规则没有说明远端 NPC 第一次出现时是：

1. 先完整生成再降级保存；
2. 只生成摘要，接近玩家时再按锁定种子补全；
3. 预留稳定 ID 和关系端点，其他字段延迟生成。

如果采用延迟生成，还需要定义关系另一端如何在未完整生成时保持可验证和不可重掷。

**关闭条件：**

1. 在上述三种策略中选择一种；
2. 定义简化快照和完整人物的字段子集关系；
3. 双向关系使用稳定 ID，不依赖显示姓名；
4. 定义未解析关系端点的合法状态；
5. 验证简化→完整→简化往返不会改变人物稳定字段。

**截止点：** NPC 聚落运行时实现之前。

## 2. P2：应进入后续清单的问题

### P2-1：生成流程图没有表达履历对后序字段的多路输入

`character-generation-rules-v0.1.md:430–443` 允许履历影响特质、价值观、红线和当前动机；`character-generation-rules-v0.1.md:521–540` 的线性流程容易被误读为后序字段只依赖紧邻步骤。

这不是逻辑矛盾。履历完全可以先生成，再在后续阶段作为共同输入。应把流程图改为数据依赖图，或注明“所有后序人格、动机和关系步骤持续读取完整履历上下文”。

### P2-2：属性与技能的相关性需要解释规则，而不是强制点数绑定

`character-generation-rules-v0.1.md:306–314` 与 `356–367` 存在沟通/交涉、思维/研究、感知/侦察等相关项。

高技能、低属性并非一定错误：长期训练可能让低天赋人物获得高技能。真正需要的是技能可追溯到履历、执行公式明确两者权重、极端组合触发解释性审查。不建议采用固定差值硬绑定。

### P2-3：MBTI 的行为权重、特质优先级和专项测试尚未定义

`character-generation-rules-v0.1.md:171–230` 已正确禁止 MBTI 决定职业、属性、善恶或服从，但 `207–217` 没有说明 MBTI、鲜明特质、价值观和红线同时生效时的优先顺序。

不应现在冻结“强 J 降低 30% 调班接受度”之类精确百分比。进入 MBTI 原型前至少应确定：

```text
行为红线
> 当前生存和医疗安全
> 明确记忆与关系承诺
> 鲜明特质和价值观
> MBTI 表达与偏好
```

具体量级再由原型调校。

### P2-4：永久加入者的成本缺少统一分类

`character-generation-rules-v0.1.md:616–624` 要求每次加入有明确成本、风险或不确定性，但未规定分类。建议至少区分供给、住房设施、医疗照护、关系制度、外部敌对以及培训排班机会成本。

### P2-5：完整示例缺少七项属性数值

`character-generation-rules-v0.1.md:712–733` 声称示例验证数据结构，但没有展示 `676` 所要求的七项基础属性。样板人物阶段应补充至少一份完整推导示例。

### P2-6：鲜明特质与核心价值观的边界仍可收紧

`character-generation-rules-v0.1.md:243–272` 中“不愿欠人情”与“欠下的债必须偿还”、“重视程序”与“合法秩序优先”存在表达重叠。

建议统一为：

- 特质回答“通常怎么做”；
- 价值观回答“为什么做、愿意保护什么”；
- 红线回答“绝不做什么，以及仍愿意做什么”。

### P2-7：属性总和 32–40 的适用范围不明确

`character-generation-rules-v0.1.md:337–346` 使用“标准人物”“通常”等词，但没有说明是否同时适用于 50 名手工人物、运行时补充人物和剧情性强势人物。需要明确超出范围的授权条件。

### P2-8：文化命名包未冻结时，姓名一致性只能人工占位

`character-generation-rules-v0.1.md:137–153` 定义命名边界，但具体文化包仍在 `832–841` 的待解决清单。在文化区域冻结前，不应把姓名兼容性列为可执行机器校验。

### P2-9：内容多样性校验需要区分统计检查和人工审查

`character-generation-rules-v0.1.md:219–230`、`684–708` 和 `758–769` 同时涉及 MBTI 覆盖、区分度指纹、创伤集中和履历相似。

类型数量、精确重复、标签频率可以自动检查；人物是否真正可区分、文化与创伤是否刻板、是否只改变效率，需要人工审查。50 人内容计划应显式安排两类审查。

### P2-10：详细人物规格先于 Gate 1 验证，存在返工风险

`character-generation-rules-v0.1.md:800–828` 已将系统分期；两周切片 `weekly-plan-production-forecast-slice-v0.1.md:72–85` 明确排除复杂关系、NPC、人口增长和完整生成。

这不构成越界，但在 Gate 1 通过前不应批量编写 50 人、实现完整生成器或冻结 MBTI 数值。Gate 1 结束后，应先用四名测试人物的真实可记忆性结果回审本规格。

## 3. 外部意见的接受、降级与拒绝

| 外部意见 | 核验结果 | 理由 |
|---|---|---|
| 履历输出与生成顺序自相矛盾，P0 | 降级为 P2-1 | 顺序未禁止后序步骤继续读取履历；问题是数据依赖表达不完整 |
| 缺少履历到数值映射，P0 | 接受为 P1-1 | 阻塞批量一致性和运行时生成，但不阻塞当前 Gate 1 |
| 团队生存校验位于单人生成阶段，P0 | 接受并合并为 P1-2 | 真实结构问题，但可局部修复，不使整份规则完全不可用 |
| 死亡补员规则缺失，P1 | 接受为 P1-3 | 需在致死切片前关闭 |
| 多项硬校验不可自动化，P1 | 接受为 P1-4 | 需要按执行者和阶段拆分 |
| 属性与技能必须做固定差值约束，P1 | 拒绝硬约束，保留 P2-2 | 低属性高技能可能有合法履历来源 |
| “接近覆盖”未定义，P1 | 接受并合并为 P1-2 | 与单人/团队校验属于同一根因 |
| 加入者成本缺少分类，P1 | 降级为 P2-4 | 当前已有成本要求，缺的是内容一致性分类 |

| 简化 NPC 与双向关系合同不足，P1 | 接受为 P1-5 | 首次生成与完整化策略确实缺失 |
| MBTI 应立即提供精确百分比，P1 | 降级为 P2-3 | 当前明确待原型验证，不宜提前冻结伪精确数值 |
| 示例、命名包、特质价值边界等 | 接受为 P2 | 真实但不阻断当前阶段 |

## 4. 与上位设计和当前 P0 的一致性

### 4.1 与 V0.4

未发现人物规则与 V0.4 已确认规则的直接冲突：

- 玩家开局 4 人、上限 10 人一致；
- NPC 聚落上限 15 人一致；
- 人物按计划和资格自主执行一致；
- 关键红线必须提前可见一致；
- 玩家无专属角色、人物不是职业棋子一致。

MBTI 是人物规则新增的待验证实现方案，不是 V0.4 强制要求。后续原型若证明无价值，可以删除或替换。

### 4.2 与 Gate 1

未发现范围越界。两周经营切片只需要 4 名具名测试人物，不要求完整传记、MBTI、复杂关系、NPC 或人口增长。本人物规则不得成为延迟 Gate 1 的前置条件。

人物规则的 Gate 1 接口只有：

- 姓名；
- 一个主要能力；
- 一个可见特点、请求或红线；
- 对计划结果的可解释影响；
- 玩家能复述的一句表达。

## 5. 建议修复顺序

1. 先修 P1-2：拆分单人、团队和运行时校验，定义基础生存活动和开局阈值；
2. 再修 P1-1 与 P1-4：建立履历节点映射和分层校验合同；
3. Gate 1 后回审 P2-3、P2-5、P2-6，用四名测试人物结果判断人格与数据粒度；
4. NPC 实现前修 P1-5，冻结简化模拟和关系端点策略；
5. 致死战斗切片前修 P1-3，冻结死亡补员；
6. 全部 P1 关闭后重新运行独立审查，目标为 `P0=0 / P1=0`。

## 6. 最终门禁

```text
P0 = 0
P1 = 5
P2 = 10
FINAL_REVIEW = FAIL
```

允许继续：

- 当前 Gate 1 两周经营切片；
- 使用现有四名占位人物验证“人物是否可被记住”；
- 为 P1 编写修订方案。

暂不建议：

- 批量编写最终 50 人库；
- 实现运行时人物生成器；
- 宣称人物规则已经通过正式审查；
- 将本审查结果视为运行时或玩家测试证据。

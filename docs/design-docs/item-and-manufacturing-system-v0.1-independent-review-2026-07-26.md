## 1. 审查范围

独立审查重点检查：

1. 与概念设计 V0.4 和 Gate 1–4 的边界是否矛盾；
2. 是否把候选内容库误当运行时范围；
3. 物品、周计划、供需预测、地图物流、人物故事和自由意志日之间的因果是否闭合；
4. 民生、主题和军备是否能够真实争夺同一瓶颈；
5. 制造、维修、拆解、品质、完整度、可获得性、来源和归属是否可解释；
6. 武器、防具、医疗、电子用具、书籍、家具、珠宝、植物和伙伴动物是否形成独特决策；

## 2. P0：冻结前必须解决

### P0-1：库存承诺的撤销与锁定规则缺失

**证据：**

- `item-and-manufacturing-system-v0.1.md:246-258`
- `item-and-manufacturing-system-v0.1.md:373-385`

文档定义了生产订单、主题交付、商队交易、战前装备和安全储备不能重复占用同一批库存，也区分了已预留、已分配和已承诺状态，但没有回答：

- 已承诺库存能否撤销；
- 不同承诺分别在何时锁定；
- 撤销贸易、主题或外交承诺的代价；
- 哪些承诺属于不可撤销；
- 未预期威胁出现后，玩家能否以明确代价重新分配。

**为什么是 P0：**

Gate 2 的核心是让主题投入与军备形成真实机会成本。如果承诺可随时无代价撤销，玩家可以先冲主题、最后转军备；如果所有承诺都绝对锁死，突发威胁又会显得不公平。

**最小修正：**

增加“承诺生命周期”合同，至少区分：

1. 草拟：不占库存；
2. 预留：占库存，可以撤销；
3. 锁定：只能承担明确代价撤销；
4. 已交付或已装载：不能直接撤销。

每类承诺需要定义：

- 锁定时点；
- 撤销条件；
- 可见代价；
- 对预测、关系、主题分数和人物记忆的影响。

### P0-2：物品与四条资源主链之间缺少映射能力

**证据：**

- `concept-design-v0.4.md:451-456`
- `item-and-manufacturing-system-v0.1.md:123-188`
- `item-and-manufacturing-system-v0.1.md:264-283`
- `item-and-manufacturing-system-v0.1.md:674-710`

V0.4 以生存、工业、安全和政治四条资源主链组织聚落经济。物品文档定义了一级分类、形态、用途标签和十五条产业链，但最小字段没有表达一件物品进入哪条资源主链。

一件金属板可以同时影响工业和安全，一批织物可以影响生存、政治或安全，因此不能只靠一级内容分类推断。

**为什么是 P0：**

没有跨链映射，就无法稳定回答：

- 哪些物品组成某条资源链的可用能力；
- 主题投入减少了多少安全能力；
- 一件跨链物品如何在供需推演中被解释；
- Gate 2 的共享瓶颈如何进入数据和 UI。

**最小修正：**

在最小数据合同中加入允许多值的主链映射，例如：

```yaml
resource_chains:
  - industry
  - security
```

同时说明：

- 主链映射不是单选分类；
- 映射表示潜在用途，不代表库存被重复计算；
- 实际占用由订单、预留和承诺状态决定；
- 政治链中的声望、信任等非物质状态不应伪装成库存物品。

## 3. P1：进入对应阶段前必须解决

### P1-1：人物与关键独立物品之间缺少引用合同

**证据：**

- `item-and-manufacturing-system-v0.1.md:220-232`
- `item-and-manufacturing-system-v0.1.md:409-421`
- `item-and-manufacturing-system-v0.1.md:753-764`
- `character-generation-rules-v0.1.md:116-131`
- `character-generation-rules-v0.1.md:352-412`

物品系统允许人物私有、临时借用、岗位配发和战前征用，也要求武器效果考虑训练和熟悉度。人物规则已有：

- 防卫技能；
- 专业经验和岗位资格；
- 工具、设施与搭档条件；
- 关系与记忆。

因此外部 reviewer 所说“人物系统没有武器能力”并不准确。真实缺口是：

- 人物数据没有引用关键个人物品；
- 独立物品没有冻结持有人物 ID 的接口；
- “防卫技能”与“熟悉某一平台或工具”的关系未定义；
- 借用、征用和归还如何进入人物记忆未定义。

**最小修正：**

在 Gate 3 前冻结双向引用原则：

- 人物只引用少量关键独立物品 ID，不复制物品状态；
- 物品实例记录当前持有者或配发目标；
- 武器平台熟悉度优先使用专业经验标签，不新增一套无限增长的熟练度系统；
- 普通批量物资不进入人物永久持有列表。

### P1-2：多个需求竞争库存时的优先级未定义

**证据：**

- `item-and-manufacturing-system-v0.1.md:246-258`
- `item-and-manufacturing-system-v0.1.md:373-385`
- `item-and-manufacturing-system-v0.1.md:484-495`

P0-1 解决“已经承诺后能否撤销”，本项解决“多个待确认需求同时存在时，谁先获得库存”。

当前没有定义：

- 安全储备是否自动保护；
- 订单是否按确认顺序、显式优先级或系统类型竞争；
- 后续订单能否抢占已有预留；
- 玩家如何看见某项确认会导致另一项停工。

**最小修正：**

- 默认按玩家确认顺序占用剩余可用库存；
- 安全储备不是绝对不可用，而是跨越时必须二次确认；
- 已锁定预留不能被后台自动抢占；
- 确认前展示受影响订单、预测和风险线；
- 不在 V0.1 引入复杂自动调度算法。

### P1-3：伙伴动物子系统规格过早

**证据：**

- `item-and-manufacturing-system-v0.1.md:964-986`
- `item-and-manufacturing-system-v0.1.md:1183`

V0.4 和 Gate 1–4 都没有伙伴动物验证项，但物品文档已经定义了需求、伤病、信任、训练、任务接受、死亡和被俘等完整角色层。

保留八个候选伙伴条目是合理的，提前冻结完整需求和行为合同会分散当前设计注意力。

**最小修正：**

当前文档只保留：

- 伙伴动物不是库存堆叠物；
- 它们进入角色实体；
- 候选作用；
- 详细子系统在 Gate 4 后单独设计。

### P1-4：“维持库存区间”订单隐藏了自动补货系统

**证据：**

- `item-and-manufacturing-system-v0.1.md:497-510`

“维持库存区间”需要：

- 最小和最大阈值；
- 检查频率；
- 自动订单生成；
- 多物品低于阈值时的产能分配；
- 与手动订单、主题、军备和安全储备的优先级；
- NPC 是否使用同一逻辑。

这比固定数量订单复杂得多，也可能替玩家自动消解本应被感知的机会成本。

**最小修正：**

- Gate 2 只使用固定数量订单模拟；
- Gate 4 再决定是否加入自动维持；
- 在引入前单独验证阈值、优先级和玩家可解释性。

### P1-5：人物技能到制造品质的接口尚未冻结

**证据：**

- `item-and-manufacturing-system-v0.1.md:315-333`
- `item-and-manufacturing-system-v0.1.md:545-559`
- `character-generation-rules-v0.1.md:352-412`

人物规则已经给出：

```text
广义技能
+ 相关基础属性
+ 专业经验或岗位资格
+ 工具、设施和搭档条件
+ 当前身体与压力状态
+ 对安排的认同程度
```

因此并非完全没有桥接接口。缺口在于物品侧没有说明这些输入分别控制：

- 能否开始工艺；
- 产量区间；
- 品质上限；
- 失败风险；
- 制作时间。

**最小修正：**

Gate 2 前先冻结职责映射，不直接冻结 reviewer 举例的技能阈值：

| 输入 | 初步职责 |
|---|---|
| 广义技能 | 产量、时间和基础稳定性 |
| 专业经验或资格 | 解锁工艺、提高品质上限 |
| 工具与设施 | 限制可达品质上限 |
| 当前状态与认同 | 扩大或缩小结果区间 |
| 材料能力 | 限制成品物理上限 |

具体阈值和公式继续留给原型验证。

## 4. P2：重要但不阻塞当前提案

### P2-1：三个 YAML 示例字段不一致

**证据：**

- `item-and-manufacturing-system-v0.1.md:1272-1349`

三个示例分别使用：

- `effect` / `known_risks`
- `allowed_uses` / `restricted_uses` / `tradeoff`
- `effects` / `risks`

即使声明不是最终运行时格式，内容编写者仍可能把它们当模板。

**最小修正：**

统一示例的基本字段，或明确这些示例分别展示不同对象层，不能混用为同一模板。

### P2-2：界面章节容易被误读为已冻结 UI 合同

**证据：**

- `item-and-manufacturing-system-v0.1.md:1044-1108`

物品详情、库存、制造和装备界面已经列出较具体的信息结构。它们作为设计方向合理，但当前尚无相应玩家测试。

**最小修正：**

在章节开头标明：

> 本节只冻结信息问题与因果可见性，不冻结布局、控件数量和交互步骤。

### P2-3：武器模块数量和类型早于 Gate 3

**证据：**

- `item-and-manufacturing-system-v0.1.md:733-742`
- `item-and-manufacturing-system-v0.1.md:1233-1249`

“0–3 个模块位”与具体模块类型尚未经过战术切片验证。

**最小修正：**

保留有限模块化和禁止随机微词条的原则，把数量和类型明确标为 Gate 3 后决定。

## 5. 建议

### 建议-1：给 220 项候选库增加预计首次导入阶段

在 `item-and-manufacturing-system-v0.1.md:1169-1195` 的表格中增加“预计首次导入”：

- G1；
- G2；
- G3；
- G4；
- Post-G4。

这只用于规划，不表示获得实现授权。

### 建议-2：废弃物优先使用简化模型

废油、污水和污染可以优先汇总为处理负担或风险值；可回收弹壳、边角料等继续使用批量库存。避免垃圾处理制造另一套微操库存。

### 建议-3：把日常用品的聚落级消费批次提升为库存原则

`item-and-manufacturing-system-v0.1.md:920` 已提出按家庭或聚落批次处理，应在库存章节中明确固化，防止后续实现退回逐人逐件消耗。

## 6. 外部 reviewer 确认的优点

Claude Code 独立确认以下方面成立：

1. **主因果链已经闭合。**  
   物品可以连接生产队列、周计划、预测、地图物流、人物来源和自由意志日。

2. **候选内容与运行时边界清楚。**  
   约 220 项是覆盖规划，不是当前导入承诺；Gate 1 仍只有化肥样本。

3. **共享瓶颈不是纯数值口号。**  
   金属板、织物、铜线、化学品、工坊时间和熟练人物时间都能形成可测试取舍。

4. **品质、完整度、可获得性和来源已正确分离。**

5. **武器方向避免随机词条和线性数值膨胀。**

6. **非战斗物品拥有实际使用情境。**  
   书籍、家具、装饰和珠宝没有被统一压成仓库被动加成。

7. **文档诚实保留了待定问题。**  
   没有把尚未验证的弹药、装备槽、伙伴动物和法律细则包装为已解决。

## 0. 修订结论

本计划只实施到 Gate 1A 报告和 Gate 1H 可测试 RC，不提前实施 Gate 2。

Gate 1 采用双轨：

- **Gate 1A — Agent Proxy：** 由测试运营负责人 agent 调度 7 个独立 agent 样本，验证流程、规则和解释是否存在阻断；
- **Gate 1H — Human Validation：** 保留 5 名首次真人玩家协议，当前暂缓；
- Gate 1A 的结论不得替代 Gate 1H，也不得解锁 Gate 2；
- Gate 2 只有在 Gate 1H 获得 `PASS` 后才允许编写规格和新开发计划。

Gate 1 采用：

```text
最小的纯 TypeScript 确定性模拟
+ 风险优先的 React 垂直切片
+ 同时支持 Gate 1A agent 证据与未来 Gate 1H 真人证据的最小匿名事件导出
```

实施顺序不再按“脚手架—完整数据合同—完整内核—完整 UI”横向铺开，而是先完成一条玩家可操作的纵向闭环：

```text
周初问题
  → 定位人物与时间块
  → 修改安排
  → 供需预测立即变化
  → 连续时间运行
  → 事件改变预测
  → 周末解释偏差
```

确认这条闭环可运行后，才扩为完整 14 日场景。

首轮不建设：

- 通用命令重放框架；
- 日末或周末检查点；
- 浏览器崩溃恢复；
- `localStorage` 会话持久化；
- 内置观察员面板；
- 自动生成 Git build metadata 的脚本；
- 数值覆盖率门槛；
- Gate 2 的 NPC、排名、豁免和 Balance Lab；
- 为未来系统预留的插件或公共 API。

Gate 2 只保留两条复用边界：

1. 继续使用同一个 React Web；
2. 继续使用无 React/DOM 依赖的纯 TypeScript 模拟内核。

Gate 1H 获得 `PASS` 后，先冻结《主题—豁免经济实验规格 V0.1》，再另写 Gate 2 开发计划。

## 1. Gate 执行合同

1. Gate 1 只实现连续两周经营切片，不包含主题、NPC、豁免、军备、外交和战斗。
2. “构建完成”只表示可以进行玩家测试，不表示 Gate 1 已通过。
3. Gate 1A 的 7 个 agent 样本必须使用同一个 Git SHA、构建编号、场景版本和固定初始状态；未来 Gate 1H 的 5 名首次真人玩家同样如此。
4. Gate 1A 只能输出 `AGENT_PROXY_PASS / AGENT_PROXY_CONDITIONAL / AGENT_PROXY_FAIL`；只有 Gate 1H 的真人报告判定为 `PASS` 后才解锁 Gate 2 规格工作。
5. `AGENT_PROXY_CONDITIONAL` 只允许修复 Gate 1A 报告列明的流程、规则或解释缺口并使用全新 agent 样本复测。
6. `AGENT_PROXY_FAIL` 时停止冻结候选 RC，根据证据修复或简化周计划模型；Gate 2 继续保持锁定。
7. 自动化和 agent 代理证据都不能替代 Gate 1H 的真人行为、主持记录和结束访谈。
8. 当前开发计划的结束点是 Gate 1A 报告和一个可供未来 Gate 1H 使用的 RC，不以 Gate 1H 执行或 Gate 2 实现作为完成条件。

固定执行链：

```text
最小纵向闭环
  → 完整两周切片
  → 内部节奏试跑
  → Gate 1 RC
  → Gate 1A 七个独立 agent 样本
  → Gate 1A 报告
  → AGENT_PROXY_PASS / AGENT_PROXY_CONDITIONAL / AGENT_PROXY_FAIL
  → Gate 1H PENDING
```

## 3. 成功标准

### 3.1 开发成功

Gate 1 RC 必须满足：

- 玩家可以从周初摘要进入完整两周流程；
- 基础计划、本周例外和即时调整按正确优先级执行；
- 修改安排会立即改变粮食或维修预测；
- 预测能解释人物、设施、道具和地图因素；
- 第 3 日水泵事件只触发一次并更新预测；
- 第二周继承第一周基础计划；
- 林禾请求形成可理解的短期产能取舍；
- 地图调整改变路径、运输损耗和粮食结果；
- 周末复盘能解释计划与实际偏差；
- 相同初始状态与相同玩家动作得到相同结果；
- 每场正式测试都从全新会话开始并能导出匿名 JSON；
- 记录可复现的机器流程耗时和速度轨迹；真人一周是否接近 6–10 分钟只由 Gate 1H 验证；
- 一条 Chromium 主流程 E2E、核心规则测试和 RC 手动验收通过。

### 3.2 Gate 1A 成功

Gate 1A 的代理结论以玩家测试协议第 10A 节为准，至少包括：

- Gate 1A 取得七个有效样本；主样本编号为 `A01`–`A07`，技术无效时使用 `A08` 起的递增替补，全部使用同一候选 RC；
- 至少 6/7 从摘要复述三个关键问题并完成两周流程；
- 第一周和第二周的有效编辑数中位数分别为 3–5；
- 至少 6/7 在第二周既不完整检查，也不完整重排；
- 至少 6/7 能根据界面指出一次预测变化的可见原因；
- 至少 6/7 能复述一名人物及其决策影响；
- 至少 5/7 通过可观察动作让地图进入决策；
- 无未解决 P0 缺陷；
- 不存在同一根因聚类包含 3 个或以上独立 P1 问题。

这些结果只能支持内部修订和候选 RC，不能证明真人体验。

### 3.3 Gate 1H 成功

Gate 1H 的最终成功仍以玩家测试协议为准，至少包括：

- 4/5 玩家能在 10 秒摘要测试后说出三个关键问题；
- 第一周和第二周分别对 5 名有效样本计算经主持人裁定的有效编辑数中位数，两周均为 3–5；不得合并 10 个“玩家—周”样本或先计算个人两周平均值；
- 4/5 玩家第二周既不完整检查，也不完整重排；
- 4/5 玩家能解释一次预测变化；
- 4/5 玩家能记住一名人物及其决策影响；
- 3/5 玩家让地图进入决策；
- 少于 3 人出现无效最高倍速等待；
- 无未解决 P0 缺陷；
- 不存在同一根因聚类包含 3 个或以上独立 P1 问题。

固定机械口径：

- 完整检查：第二周检查至少 3/4 人物行且覆盖至少 5/7 日期组，或玩家明确表示必须重新检查全部计划；
- 完整重排：第二周修改至少 16 个活动块，或日程修改同时影响至少 3 人并跨至少 5 天；
- 独立 P1 问题：同一可复述症状影响至少 2 名有效玩家；
- 根因聚类：多个独立 P1 问题归属同一界面表达或规则根因。

详细记录和裁定方式以玩家测试协议第 8.1、8.8 和第 10 节为准。

## 4. Gate 1 范围与削减线

### 4.1 RC-Must：RC 必须具备

**固定场景**

- 连续 14 日；
- 4 名具名人物；
- 每人每天 4 个可编辑活动块；
- 粮食与维修保障两条供需；
- 农田、水泵、粮仓和维修工坊；
- 一次化肥机会；
- 第 3 日水泵故障；
- 第二周林禾学习请求；
- 农田—粮仓运输瓶颈；
- 可直接运行的基础日程。

**玩家流程**

- 默认入口为 3–5 张周初例外卡；
- 点击卡片定位人物、活动块、预测行或地图路径；
- 支持单格编辑、批量选择后统一修改、复制单日和撤销；
- 修改时选择“仅本次 / 本周同类 / 设为后续基础计划”；
- 粮食与维修预测显示区间、状态、趋势和主要原因；
- 支持主动接受轻度缺口；
- 暂停、1×、3×、8×速度；
- 重大事件自动暂停；
- 简单 SVG/DOM 地图和人物位置；
- 集货点或短路调整；
- 周末 3–5 项偏差复盘；
- 第二周继承与例外状态可区分。

**测试支持**

- 新会话初始化；
- 连续且不复用的匿名编号 `P01`–`Pnn`；
- 构建编号、Git SHA、场景版本和固定种子元数据；
- 最小事件日志；
- 测试结束 JSON 导出；
- 明确的“结束并清空会话”操作；
- 一条主流程 E2E；
- 1440×900 和 1280×720 手动验收。

### 4.2 RC-Optional：只有 RC-Must 稳定且仍有时间才做

- 更平滑的人物移动插值；
- 拖动选择多个活动块及其交互反馈；
- 完整网格级键盘批量编辑；
- 1024×768 布局精修；
- 第二条以上 Playwright 分支路径；
- 更丰富的预测展开动画；
- 附加调试面板。

RC-Optional 未完成不能阻止首次玩家测试，只能作为已知限制记录。基本可访问名称、可见焦点、按钮键盘激活和非颜色状态表达仍属于 RC-Must。

### 4.3 Gate 1 明确不做

- 月度主题、排名和豁免；
- NPC 聚落；
- 武器、军备和战斗；
- 外交和交易；
- 复杂心情、关系和成长；
- 随机事件池；
- 完整建造或科技树；
- 通用保存系统；
- 通用重放系统；
- 云端遥测、账号和后端；
- 正式美术、音效和移动端适配。

### 4.4 延期时的固定削减顺序

若 D14 代理试玩 C 前仍未形成稳定完整两周流程，按以下顺序削减：

1. 人物移动插值和非必要动画；
2. 1024×768 精修；
3. 第二条以上 E2E；
4. 完整键盘批量编辑，只保留基本键盘激活；
5. 附加调试与可视化信息。

不得削减：

- 周初摘要；
- 计划—预测双向联动；
- 水泵事件；
- 第二周继承；
- 林禾请求；
- 地图瓶颈与可操作调整；
- 周末偏差解释；
- 新会话、匿名记录和导出。

若削减 RC-Optional 后 RC-Must 仍不能稳定运行，应推迟 RC，不得以残缺流程招募正式 Gate 样本。

## 5. 技术基线

| 项目 | 决定 |
|---|---|
| 应用目录 | `prototype/` |
| UI | React 19 函数组件 |
| 语言 | TypeScript 严格检查 |

- Redux、Zustand 或其他全局状态库；
- React Router；
- 图表库；
- 拖拽库；
- Canvas/WebGL 游戏框架；
- 后端、数据库、身份认证或云遥测；
- Schema 运行时库；
- CSS 框架或组件库。

### 6.1 模拟边界

`sim/` 是唯一规则真相源：

- 不导入 React 或浏览器 API；
- 不读取真实时间；
- 不调用 `Math.random()`；
- 使用整数 tick；
- 不修改输入状态；
- 相同场景版本、初始状态和动作序列必须得到相同结果。

React 只负责：

- 保存当前内存状态；
- 收集玩家输入；
- 调用模拟函数；
- 呈现 selector 结果；
- 驱动外部时钟；
- 记录不影响规则的界面事件；
- 导出测试数据。

### 6.2 最小数据合同

Gate 1 只冻结当前切片真正需要的语义：

```ts
export interface ScenarioDefinition {
  id: string
  version: string
  fixedSeed: number
  time: TimeConfig
  createInitialState(): SimulationState
  scriptedEvents: readonly ScriptedEvent[]
}

export interface PlayerActionEnvelope {
  id: string
  sequence: number
  atTick: number
  undoesActionId?: string
  action: PlayerAction
}

export interface TransitionResult {
  state: SimulationState
  events: readonly DomainEvent[]
}

export function applyPlayerAction(
  state: SimulationState,
  action: PlayerAction,
  scenario: ScenarioDefinition,
): TransitionResult

export function advanceSimulation(
  state: SimulationState,
  targetTick: number,
  scenario: ScenarioDefinition,
): TransitionResult
```

约束：

- `createInitialState()` 是唯一初始状态来源；
- `fixedSeed` 只作为固定测试场景元数据，不扩散为当前所有函数的参数；
- 每次确认提交只生成一个稳定动作 ID；批量修改的受影响格子保存在同一动作中，撤销和重做引用原动作 ID；
- `advanceSimulation()` 先按 tick 处理截至目标 tick 的脚本事件，再返回给 UI 接受玩家动作；同一 tick 上脚本事件先于随后提交的玩家动作；
- 动作日志用于测试导出和问题复盘，不承诺通用重放；
- 接口名称只服务 Gate 1，不作为未来公共 API；
- Gate 1 玩家证据若否定逐人时间块模型，允许重写这些合同。

### 6.3 时间初始参数

第一版统一使用：

- 1 tick = 10 游戏分钟；
- 1× 时每 tick 250 毫秒；
- 速度档位为暂停、1×、3×、8×；
- 固定步长只影响模拟推进，不依赖浏览器渲染帧数；
- 测试入口允许直接推进到指定 tick，Playwright 不等待真实游戏时间。

这些数值是内部试跑的起始参数，不是最终产品承诺。D14 代理试玩 C 只记录机器流程耗时、速度档位和等待轨迹，不承担真人“一周 6–10 分钟”验收；该目标留给 Gate 1H。

经营周统一计时为：

- 第一周从周初摘要首次显示开始，到第一周周末复盘首次显示为止；
- 第二周从第二周摘要首次显示开始，到第二周周末复盘首次显示为止；
- 包含 10 秒摘要测试、玩家规划、暂停思考、时间运行和主持提示；
- 不包含结束访谈；
- 技术中断单独记录并从原始时长中扣除；
- Gate 报告同时保留原始完成时长、技术中断时长和净完成时长。

## 7. 测试会话与证据来源

### 7.1 新会话

每场测试开始前由主持人输入：

- 匿名编号；
- 构建编号，格式 `g1-rc-YYYYMMDD.N`；
- Git commit SHA；
- 场景版本；
- 固定种子；
- 分辨率和输入设备。

开始会话时必须：

1. 创建全新初始状态；
2. 清空内存中的动作与遥测；
3. 不读取上一名玩家的任何数据；
4. 显示当前匿名编号和构建编号；
5. 经主持人确认后进入 10 秒摘要环节。

测试结束：

1. 导出匿名 JSON；
2. 主持人确认文件已保存；
3. 执行“结束并清空会话”；
4. 返回空白会话初始化页。

发生崩溃时不自动恢复。按玩家测试协议记录阻断、是否重开和无效原因。

### 7.4 Gate 1H 真人样本、替补与复测

本节只适用于暂缓的 Gate 1H。真人样本以玩家测试协议第 3.1、3.2 和第 4 节为权威合同。本计划固定以下实施边界：

1. RC 前建立至少 7 名合格候选人的受控台账，匿名编号按 `P01`、`P02`……连续分配且永不复用；
2. RC 前冻结测试顺序；不得根据已出现的结果或候选人倾向选择后续样本；
3. 只有错误构建或场景、已接触设计、主持人泄露答案、不可恢复技术故障、主动退出五类预先冻结原因可以使场次无效；
4. 负面评价、差策略、理解失败、触发 P0/P1 或不愿继续游玩均不得作为无效理由；
5. 无效场次保留原始记录，替补使用台账中的下一个新编号，直至取得 5 名有效样本；
6. 同一 Gate 判定不得混用规则修改前后的样本；
7. `CONDITIONAL PASS` 的正式复测必须使用新的首次玩家和继续递增的新编号；原玩家复玩只作诊断。

测试负责人维护候选人台账、无效裁定与替补顺序；实施负责人只提供冻结 RC、构建元数据和可验证日志，不得决定保留哪些玩家结果。

### 7.5 Gate 1A 独立 agent 样本

Gate 1A 由当前主 agent `/root` 担任测试运营负责人。主样本使用 `A01`–`A07`；若样本技术无效，保留原记录并从 `A08` 起递增替补，直到取得七个有效样本。

固定调度合同：

1. 七个样本只在正式 RC 冻结后实例化，不能提前阅读原型、设计文档或其他样本记录；
2. 每个样本使用全新 agent 会话并设为干净上下文，不继承本任务对话；
3. agent 只获得玩家入口、控制说明、中性目标和匿名编号，只能通过玩家界面操作；
4. agent 不读取仓库设计或实现文件，不修改代码、配置、测试数据和其他样本记录；
5. 七个样本使用同一 Git SHA、构建编号、场景版本、固定种子和初始状态；
6. 受当前最多 4 个并发 agent 槽位限制，测试运营负责人按 `3 + 3 + 1` 三批调度；批次之间不得向后续样本泄露先前结果；
7. 每场保存匿名导出、结构化任务结果、阻断点和工具故障；测试运营负责人在全部七场结束后统一聚类；
8. agent 的理解失败、差策略、负面评价或触发 P0/P1 不能被判为技术无效。

里程碑代理试玩 A、B、C 将在 D4、D9、D14 分别以新的干净上下文执行；它们接触开发中构建后只用于内部阻断检查，不得计入 `A01`–`A07`。

## 10. 测试计划

### 10.1 模拟合同测试

- 相同初始状态和动作序列得到相同最终状态；
- 同一 tick 上先处理脚本事件，再处理事件返回后提交的玩家动作；
- 预防维修与忽略维修产生不同且可解释的结果；
- 水泵事件只触发一次；
- 本周例外在周末失效；
- 长期基础计划只有明确操作才能改变；
- 林禾请求接受和拒绝均能完成两周；
- 地图调整改变路径、损耗和粮食预测；
- 不操作也能完成两周但留下代价；
- 两条人工策略都可运行；
- 只加班不能同时解决全部问题。

不设置数值覆盖率门槛。失败路径和玩法合同优先于行覆盖率。

### 10.2 组件测试

- 首屏是周初摘要，不是完整 112 格表；
- 问题卡能定位相关人物、时间块和预测；
- 修改安排立即改变预测与文字原因；
- 主动接受风险后不重复催促；
- 第二周继承与例外视觉可区分；
- 颜色之外存在文字、图标、数值区间和趋势；
- 新会话不会继承上一场内存数据；
- 每个候选编辑组都有稳定动作 ID，撤销和重做能追溯到原动作；
- 导出不包含真实姓名或自由文本笔记。

## 12. 主要风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 再次横向铺设基础设施 | 代理试玩 A 仍没有可玩的完整闭环 | 停止扩展，先打通一条纵向流程 |
| 周计划仍像表格 | 首屏或主要操作依赖完整 112 格 | 摘要为默认入口，只定位必要例外 |
| 预测正确但不可信 | 玩家只能复述颜色或数字 | 强制显示人物、设施、地图和事件原因 |
| 地图只是被动百分比 | 玩家不看人物或路线也能最优 | 让调整同步改变路径、损耗、预测和复盘 |
| 真实节奏过慢 | 内部试跑长期最高倍速 | 调整 tick、倍速和自动暂停，不增加空事件 |
| 测试样本串档 | 新测试者看到上一局状态 | 会话仅存内存，结束后显式清空 |
| 自动数据替代人工判断 | 日志被用来推断玩家口头理解 | 固定指标来源表，口头指标只由主持记录 |
| 样本失效被事后选择 | 负面结果被排除，或替补复用旧编号 | RC 前冻结台账、无效条件和顺序；无效记录保留 |
| agent 样本上下文泄漏 | 后续样本知道设计答案或前序缺陷 | RC 后才实例化，使用干净上下文，按三批隔离结果 |
| Gate 1A 被误当真人证据 | 报告出现乐趣、认知负担或“玩家已验证” | 只允许代理结论；Gate 1H 继续 `PENDING`，Gate 2 继续 `LOCKED` |
| Gate 2 偷跑 | Gate 1 出现 NPC 或排名字段 | 删除预留代码，等待 Gate 1H PASS |
| 批量编辑阻塞主流程 | 玩家无法稳定选择多个块并统一修改 | 修复批量选择；拖动选择保持 RC-Optional，不引入拖拽库 |
| Gate 1A 运营晚于开发 | D13 尚未冻结 agent 测试包与席位 | D1 建立合同与 Issues，D15–D18 只核对 RC 元数据 |
| 单一 agent 混合实施与裁定 | 实施者选择性解释代理结果 | 测试运营负责人和七个样本会话分离；保留原始导出后统一裁定 |
